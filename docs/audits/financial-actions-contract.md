# Native financial action contracts

Canonical route permissions and features are in `Thorbis-TanStack/services/api/src/routes/manifest.ts` (also generated into `services/api/openapi.json`). The route handlers in `services/api/src/app.ts` and domain schemas/commands cited below resolve request details omitted from OpenAPI. JSON success responses below are domain records unless stated otherwise; examples are shapes, not live data.

| Action | Capability / feature | Request body | Successful response |
|---|---|---|---|
| `POST /v1/estimates/{id}/send` | `estimate.send` / `estimates` | `{ "expectedRevisionNumber": 0 }` for a never-issued draft; use the currently observed revision for a revised draft | updated `Estimate` (`status:"sent"`, incremented `currentRevisionNumber`) |
| `POST /v1/estimates/{id}/approve` | `estimate.approve` / `estimates`; `progress_billing` additionally if `depositRequired` present | `{ "revisionNumber": 1, "depositRequired"?: {"amount": positive integer cents,"currency":"USD"} }` | updated `Estimate`; approval may create a Job |
| `POST /v1/estimates/{id}/decline` | `estimate.approve` / `estimates` | `{ "revisionNumber": 1 }` | updated `Estimate` |
| `POST /v1/estimates/{id}/revise` | `estimate.create` / `estimates`; `estimate.discount` for credit lines, `estimate_option_signing` if options present | `{ "expectedRevisionNumber": 1, "title": string, "lines": [1–500 estimate line inputs], "options"?: [up to 8 options] }` | updated `Estimate` as replacement draft |
| `POST /v1/jobs/{id}/completion-invoice` | `invoice.create` / `invoicing` | no body/empty JSON | `Invoice` draft derived from canonical job and approved estimate facts |

| `POST /v1/invoices/{id}/discount` | `invoice.discount` **and** `invoice.view` / `invoicing` | `{ "description": string, "amount": {"amount": positive integer cents,"currency":"USD"} }` | updated draft `Invoice` |
| `POST /v1/invoices/{id}/payments` | `invoice.payment.create` / `payments`, online required | `{ "amount": {"amount": integer cents,"currency":"USD"}, "method": "card"\|"ach"\|"cash"\|"check", "idempotencyKey": string (1–200) }` | `Payment` with HTTP 201 |

Send, approve, and decline accept optional JSON at the HTTP handler, but **native clients should send explicit revision numbers**. An omitted send precondition aliases zero and cannot address later revisions; omitted approve/decline addresses only revision 1 during a temporary compatibility window. Each checks the current revision and returns 409 on mismatch. Send is draft→sent; a precise replay is idempotent. Approve/decline require sent status and precise revision. An estimate with options requires previously bound customer selection and signature evidence before approval; `POST /approve` does not create that evidence. Approval's deposit flag requires `progress_billing` before commit. Sources: `domains/estimates/src/schemas.ts:283-327`, `domains/estimates/src/commands.ts:199-272,371-501,610-650`, `services/api/src/app.ts:3178-3207`.

Invoice issue checks `expectedLinesRevision` against the reviewed draft and is idempotent after the issuance snapshot exists. The draft's lines are immutable once issued. The old `POST /v1/invoices/{id}/lines` deliberately returns a migration conflict; use `/v2/...`. Sources: `domains/invoicing/src/schemas.ts:719-742`, `domains/invoicing/src/commands.ts:1277-1355`, `services/api/src/app.ts:4988-5010`.

## Payment provenance and UI truth

`Payment` requires `id,organizationId,invoiceId,amount,method,status,collectionEvidence,idempotencyKey,recordedAt`; `refundedAmount,netAmount,refundedAt` may be absent. Status is `recorded|refunded`. Evidence is `{purpose:"physical_service",source:{kind:"job"|"billing_schedule"|"manual_physical_service_evidence",id:uuid}}`; historic `unclassified_legacy` rows can be read but are **not** physical-service proof. The client sends no provenance field: the server derives it from the invoice source. Recording fails with 409 if no physical-service collection evidence exists. The server also checks invoice balance and tenant-wide idempotency: identical key + invoice + amount + method returns the recorded payment; a key reused for a different intent is 409. Source: `domains/payments/src/schemas.ts:3-62`, `domains/payments/src/commands.ts:143-225`.

Card collection is a separate processor workflow. A 201 response may have a `clientSecret` or an attempt without a canonical Payment. A 202 reconciliation response cannot be treated as paid. Only a canonical Payment or reloaded Invoice ledger projection should drive a paid badge. Hosted pay-link creation also does not constitute payment; it returns a short-lived external checkout URL. The direct record route supersedes an open pay link before recording. Source: `services/api/src/app.ts:5083-5185`, `services/api/src/routes/manifest.ts:4644-4738`.

## PDFs and commercial documents

`GET /v1/estimates/{id}/document`, `GET /v1/estimates/{id}/revisions/{revisionNumber}/document`, and `GET /v1/invoices/{id}/document` require `estimate.view`/`estimates` or `invoice.view`/`invoicing` respectively. They return **PDF bytes**, not JSON, with `Content-Type: application/pdf` and inline filename. Estimate revision document is immutable issued-revision paper; current document follows current record projection. Source: `services/api/src/app.ts:3133-3164,4812-4820`, `services/api/src/composition/document-pdf.ts:19-34`, `services/api/src/routes/manifest.ts:3222-3253,4481-4492`.

There is also a write-once commercial-document API: `POST /v1/{estimates|invoices}/{id}/commercial-documents/preview` (view permission), `POST .../commercial-documents` and `POST .../{contentHash}/render` (estimate.send or invoice.issue), `GET .../{contentHash}` and `GET .../{contentHash}/artifacts/{artifactHash}` (view), plus `POST .../{contentHash}/verify` (view). The issue/preview body can contain a `presentation`; commercial truth/content supplied by the client is rejected. These endpoints return content/snapshot metadata or artifact bytes and do not replace the simpler PDF GET for native preview. Source: `services/api/src/composition/commercial-documents.ts:107-136`, `services/api/src/app.ts:3450-3540,4812-4980`, `services/api/src/routes/manifest.ts` commercial-document entries.
