# Offline job-note provenance implementation plan

**Goal:** Make job-note activity selectable and usable offline with verified ownership, truthful save state and no stale cross-authority publication.

**Architecture:** Persist a verified authority epoch and API origin with the Keychain session snapshot, then use versioned actor/workspace/job/epoch cache envelopes and publication scopes. Route note mutations through a server-verified idempotent operation or explicit uncertain recovery. The [design](../specs/2026-10-30-offline-job-notes-provenance-design.md) specifies security, migration and offline constraints; this plan does not authorize release of the held branch.

**Review focus:** cold offline restore and expiration; same-version revoke/regrant; actor/workspace/origin/job switch; crash or Keychain/cache failure; ambiguous note response and duplicate retry.

1. **Verify contracts first.** Inspect actual backend authority generation, per-job authorization, command receipt/idempotency and REST note fallback. Record exact source and tests. If no safe idempotent path exists, define uncertain recovery without auto-retry; do not invent a server guarantee.
2. **Authority snapshot.** Add origin and durable epoch; make Keychain snapshot persistence observable. Write tests first for unchanged revalidation, changed capabilities/features, same-version revoke/regrant, wrong origin/identity, expiration, failure and restart. Verify safe ordering under interruption and preserve the existing cold-offline session when its snapshot matches.
3. **Cache envelope.** Add versioned protected atomic job-note cache under collision-resistant identity keys; validate every record. Test matching cold offline restore, actor/workspace/job/origin/epoch mismatch, malformed data, crash/write failure and legacy file preservation. Do not bind unowned legacy data to a current user.
4. **Publication and UI.** Bind displayed notes and pending entries to source scope, hide synchronously on invalidation, reject late responses and cursor writes, keep full text and status, and only enable fallback for proven provenance. Test revoke/regrant, overlapping loads, job changes, cached offline use, and queued pending/rejected notes. Exercise large text and VoiceOver, then inspect screenshots.
5. **Mutation and recovery.** Capture a stable operation before sending, guard completion and identity, check persisted result before clearing drafts, and implement only the backend-verified idempotent retry path. Test lost response after commit, retry/relaunch, stale authority and scope change, storage failures, validation and conflict without losing draft or duplicating notes.
6. **Review and rollout.** Independently review identity/privacy/offline and financial-adjacent activity behavior, validate feature retention and supported iPhone/iPad journeys, write honest limits and release notes, audit the signed artifact and verify TestFlight processing/tester access. Keep incomplete paths held until the evidence passes.
