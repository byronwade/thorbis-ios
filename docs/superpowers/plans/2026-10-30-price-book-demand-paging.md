# Demand-paged price book with offline search

## Outcome and scope

Show a useful first page without waiting for every price-book item, fetch further results on demand, and retain the full automatic offline book and the existing picker semantics. Do not claim complete search, totals, current prices or offline availability until the corresponding source proves them. This plan covers the estimate and invoice picker and the standalone price-book list; jobs, customers and photos need their own paging contracts.

## Existing contracts and gaps

- `APIClient.priceBookItems` in `Thorbis/Sources/WorkspaceAPI.swift` calls `GET /v1/query?resourceId=price_book_items&purpose=collection&limit=...&cursor=...`; it validates the collection schema and ID. `PriceBookCatalog.load` in `PriceBookSearch.swift` requests pages of 200, gathers all of them, and publishes/writes the snapshot only on completion. The picker uses the full local `PriceBookSearchIndex`, which handles word prefixes, one typo, normalized joined model numbers, unit/kind terms, per-device frecency, exclusions and stable result paging. Search, indexing and cache serialization currently touch the main actor. The cache optimization in commit `2a1842e` addresses repeated ranking only, not cold or network loading.
- Server collection pagination is bounded (default 50, max 200) and authorized by resource and scope; the PostgreSQL adapter joins current price-book revisions. Filters support description/unit `contains` or `starts_with` and kind `is`/`is_any_of`, but are not equivalent to the picker matcher. Collection `purpose=picker` omits the price/revision fields required to create document lines; use a complete authorized projection.
- `domains/price-book/src/query-platform-extension.ts` registers no search source. Generic search has token/trigram machinery but caps candidate acquisition at 50 before result paging (`packages/query/src/search-candidates.ts`); registering a source alone cannot guarantee all matches or existing ranking. Its trigram semantics differ from the Swift matcher.
- `packages/sync/src/scope.ts` permits the `price_book_items` stream only under organization scope with `pricebook.view`; PowerSync rules replicate items and revisions. The web local DB schema/reader includes these tables, but the native iOS app does not currently consume that replication path. Existence of the web sync rules is not proof that iOS can use them safely or that production is configured.
- Item selection must retain the canonical item ID, revision, amount, currency, unit and tax classification; estimate and invoice server commands resolve and authorize revision provenance. Existing offline snapshot behavior and the contract that local frecency never leaves the device must not be silently removed.

## Hard design constraint: private frecency across pages

The current ranking sorts by match tier, then private device-local frecency, then description length and localized name. A server that has not received usage data cannot know the exact order within a tier, while a client that has read only the first page cannot guarantee that a later page contains no more-frequent item. Sending usage or a list of frequently used IDs would change the existing privacy contract. Therefore do not claim exact global order on a cold, incomplete local snapshot, and do not quietly transmit usage. Ship complete offline search/ranking from a verified local snapshot; any initial online search must be marked incomplete until an explicitly specified privacy-preserving merge proves parity. If that merge cannot meet latency and correctness, retain the existing loading state until the snapshot is ready rather than falsely claim equivalent ranking.

## Work packages

### 1. Lock a shared, versioned search contract

1. Produce golden vectors from `PriceBookSearchTests` and the actual Swift index: punctuation/accent folding, multiword order, exact/prefix/contains/one-typo tiers, partial final word, joined `R410A` and `R-410A`, no fuzzy numeric match (`10mm` vs `110mm`), unit, singular/plural kind, archived and non-USD exclusions, highlighting, and tie-breaking. Include empty queries, long strings and adversarial repeated tokens.
2. Specify normalization and ranking precisely across Swift, server and local storage, including Unicode/collation behavior. Add cross-runtime fixtures and reject implementation drift. Do not assume `pg_trgm` is identical to the existing edit-distance rule or that localized Swift sorting equals PostgreSQL collation.
3. Define how private frecency is merged without sending usage: a local snapshot/index can compute exact ordering; any online-before-completion path must explicitly identify what remains unproven. Resolve the mathematical completeness problem before claiming parity. Preserve custom-line entry, filters, recent items, page navigation and selected quantities.

### 2. Add an owner-authorized bounded backend search

1. Follow the backend `pnpm thorbis context`, owner extension/generator and route-manifest workflows. Add a price-book-owned query/search operation, or extend the registered search infrastructure only after addressing its 50-candidate ceiling. Use indexed candidate retrieval plus exact matcher verification so all matches, including late matches and typo/model cases, are reachable. Establish hard query/candidate/resource limits and benchmark large and low-selectivity terms; no offset scans.
2. Return bounded `items` with authoritative item ID/current revision, description, unit, kind, sell amount, currency, tax classification and archive/selectability state, plus an opaque cursor, matcher version and snapshot/freshness information. Validate authorization and feature entitlement on every request and derive tenant exclusively from the authenticated context. Do not expose storage keys or user-supplied tenant authority.
3. Define a deterministic keyset containing all server-visible rank components and ID tie-break; bind cursor to normalized query, filter, page size, matcher/sort version, snapshot generation, actor/organization and relevant authorization epoch. Reject or explicitly restart stale/tampered/cross-scope cursors. Define behavior for revisions/archive/insertions between pages; avoid gaps, duplicates or asserting a complete stable snapshot without a snapshot guarantee.
4. At add/save time continue resolving the selected revision through existing estimate/invoice authority. A stale, archived, revoked or changed item must surface a recoverable conflict rather than silently changing the line or fabricating an amount. Price, revision and scope are not inferred from a label or cache alone.
5. Test the shared matcher vectors, >600 and >50 equal-tier matches across all pages, numeric/model edge cases, deterministic ordering/tie-breaks, cursor changes and expiry, concurrent insert/revise/archive, tenant and scoped access, capability loss/regrant, malicious cursors, partial failures and immutable price/revision selection. Exercise actual PostgreSQL indexed plans and bounded memory, not only the memory adapter (which currently loads multiple complete collections).

### 3. Build an incremental native offline index

1. Implement an iOS-owned, tenant/session-bound durable local index (or adopt the existing scoped replication protocol only after validating its native SDK, licensing, security, schema and server configuration). Store authorized current catalog snapshots and provenance with appropriate data protection, and support query/paging by a bounded local result window. Do not call the TypeScript `@thorbis/local-db` directly from Swift or assume the web stream is already installed on iOS.
2. Bootstrap and refresh in bounded pages/stream chunks with backpressure, away from the main actor. Open the picker and render its first available results without allocating/rendering the whole book. Continue the existing automatic offline provisioning in the background; an optional manual download may supplement it, not replace it. Persist page checkpoints and a completion/generation marker; never write a partial snapshot over the last complete authorized snapshot.
3. Bind each request, cache, cursor and outstanding task to actor, organization, session generation, capability/authority revision, API origin and request generation. On account/workspace/access change synchronously hide stale data, cancel/ignore late completions and purge or reauthorize data according to the existing security policy. Do not restore cached rows solely because a later grant looks similar.
4. Represent fresh/complete, syncing/partial, offline complete, stale, revoked and failed states explicitly. Never show “no matches,” total counts or a completed offline guarantee from a partial index. Retry without duplicating rows, retain prior valid snapshot during failed refresh, and recover safely across relaunch; downloaded and pending counts must describe what is actually known.
5. Keep search/index work off the main actor with debounced, cancellable request generations. Page locally in stable order; clear stale selections when query, category or authority changes. Preserve the current selection/price snapshot semantics and local-only usage. Use lazy SwiftUI containers and stable IDs, but verify with actual Instruments on device rather than infer frame performance from row count.

### 4. Integrate and qualify

1. Add client contract tests using delayed/out-of-order responses, repeated/stale cursors, query/filter changes, complete vs partial disk snapshots, offline first use, revocation during fetch, same-org account replacement, changed revisions, failed refresh, duplicate IDs and eventual full offline availability. Cover estimate and invoice selection plus standalone price book. Verify the previous complete snapshot cannot leak after authority changes.
2. Run server contract/security and indexed-query tests, exact matcher parity, targeted iOS unit/UI tests (including a match after item 600 and price/revision integrity), and accessibility/VoiceOver pagination. Capture before/after first useful content time, request count/bytes, p95 search latency, frame hitches and peak memory on representative physical iPhones with 600 and larger catalogs, cold/warm/offline. Record network, device, build and dataset; do not extrapolate a synthetic host benchmark.
3. Deploy backend compatibly first, run migrations/index checks and feature-gate the new operation. Verify authorization, production configuration and rollback. Ship the app only when backend is deployed and tested; retain the prior complete offline behavior on servers lacking the new contract. A feature flag must not create an online-only dead end. Archive, audit and upload a uniquely versioned TestFlight build, then verify processing and group availability.

## Done means

First-page retrieval and rendering do not require downloading or instantiating 600 rows; further pages are requested on demand; the full book becomes automatically available offline; complete fuzzy/model search, private frecency and revision authority match the existing behavior; and all partial, stale, permission and failure cases are truthful and recoverable. This plan is not implementation or evidence that those conditions already hold.
