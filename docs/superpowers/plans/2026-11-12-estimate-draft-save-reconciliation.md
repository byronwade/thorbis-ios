## Work and validation

1. **Freeze and reconcile the server base.** Create a separate backend worktree from freshly fetched main, record its commit and current production deployment, and compare all held changes by semantic unit rather than cherry-picking migration history. Verify the current estimate/line-group schema, old writer, revision, customer-action, job-origin and billing invariants. Reconcile offered-item lineage and existing feature flags before designing any migration.
2. **Version and lock the owning draft.** Under the tenant-scoped estimate lock, require current `estimate.create` resource authorization, a supported contract, exact expected draft edit version and issued revision. Preserve complete options, current line IDs, source evidence and customer visibility/group metadata. Increment the version atomically on every managed edit/reopen; reject sent or approved in-place writes. Issue/send must bind the exact draft version. Generate new successor migrations from the actual latest main, preserving all existing migrations and old-writer fencing.
3. **Preserve financial and retry authority.** Integrate canonical Price Book and discount/concession checks and feature admission for both retained and newly selected lines. Never drop offered scope or replace server-owned provenance from client input. Bind durable command receipts to actor, tenant, target and normalized full intent; reauthorize every replay, reject mismatched key/intent, and preserve the original result after an unknown response. Do not silently fall back to unconditional or legacy writes.
4. **Prove the server contract.** Add real PostgreSQL runtime-role tests with deliberately held row locks for save/save and save/send in both orders; immutable issued evidence and approved-scope tests; cross-tenant/RLS/permission-revocation tests; old-writer and migration-upgrade tests; exact receipt replay, lost response, changed actor/intent and feature hold/rehold tests. Run domain, API, sync, generated schema/OpenAPI and full project gates at frozen source, followed by independent financial/security review. Keep feature unexposed until deployment and authenticated capability are verified.
5. **Build the native editable workspace only against that contract.** Bind the loaded record, job, session/origin and server capability to the editor. Preserve unsaved work across navigation/reconnect and fail closed on identity, permission or capability changes. Send expected versions and stable retry identity; offer explicit conflict, unavailable, and uncertain-outcome recovery without discarding edits. Keep existing customer presentation, document activity, signing and actions accessible. Sent/declined work uses canonical revision; approved work requires a separately qualified change order. Do not claim paragraphs, display controls or customer add-ons until their respective server contracts exist.
6. **Qualify the full journey.** Test draft first/repeated save, two editors, save-versus-send, long-text rejection without loss, lost-response retry, option/credit/source preservation, session/workspace replacement, unsaved navigation, sent revision and approved lock. Exercise phone and iPad, customer handoff and signed artifact; independently review the final combined source and verify deployed capability before TestFlight upload.

## Scope

Useful independent work is read-only contract and migration reconciliation plus tests on a disposable local backend. Opening the existing unsavable form by default, inventing a client-only price/quote, or treating partial historical evidence as a deployed contract would mislead technicians or risk commercial data.
