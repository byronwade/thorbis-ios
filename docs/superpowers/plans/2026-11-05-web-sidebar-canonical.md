# Canonical web sidebar on iOS

Use the Thorbis-TanStack navigation registry and `AppSidebar` as the source of hierarchy. Render personal destinations, then collapsible Favorites, followed by workspace rows: a workspace with multiple permitted native children opens its first available child and shows indented children only when one is active; a single child is a direct destination. Keep device-only and mobile-only features truthfully labeled and reachable. Keep existing user pins and global ordering via an initially expanded, collapsible Your places list rather than discarding them. Keep the existing phone Recent section independently collapsible. Hold adding Recent to iPad until origin and resource authorization are proven; do not extend persisted-title exposure. Never add routes that iOS does not implement. Confirm role filtering, ordering, 44-point accessibility, active workspace and exact single-child behavior with unit and mounted tests; run focused checks on both device classes and add release notes.
