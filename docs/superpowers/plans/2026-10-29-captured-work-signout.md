# Preserve notes and captures through sign-out review — implementation plan

Status: **design for review; no protection is implemented by this document**. The activity/sign-out branch remains held. A badge or counter alone cannot preserve work.

Independent read-only review identified late-callback resurrection after confirmed deletion, final-keystroke and multiwindow conflicts, unbounded picker acquisition, aborted workspace switches, offline authority and platform-callback lifetime as required constraints. Those findings are incorporated below; review did not verify an implementation or run tests.

## Reproduced source seams

- `JobDetailView` owns typed `note` in local `@State`. `App.appContent` recreates `RootView` when `session.generation` changes and removes it when the session leaves `.ready`; the note is not part of the durable outbox until `saveNote()` successfully enqueues it. The existing original-text check prevents clearing later edits after a completed save, but does not preserve that text when the view is destroyed.
- `JobMediaView` owns `selectedData`, picker state and capture context in local `@State`. `.onDisappear` sets `selectedData = nil`. `PhotosPickerItem.loadTransferable` runs asynchronously in a view-created task; camera, scanner and document-import callbacks can return after a session or view change. A successful `PendingMediaStore.save` produces an actor/workspace/origin/job-bound protected file, but it rejects a retired context, and failed saves leave bytes only in the view. A picker or camera that is still active has no saved bytes to count.
- `SessionController.invalidate` advances session generation and clears verified actor/workspace; `App` unbinds the media store and swaps the root UI. The existing `InboxLocalDrafts` clears in-memory contents on identity change and is not a persistence/recovery solution for job notes or media.
- A context-bound queue/media save and the WIP saved-work gate cover an item only after it reaches their owners. The gate and inventory prototype are not wired to sign-out, and `clearAll` does not prove deletion. The existing sign-out policy removes local copies, while older photo files are unscoped.

## Required behavior and boundaries

1. A root-owned captured-work coordinator must outlive a job view and `RootView` generation. It owns each note draft, picker transfer, camera/scanner callback and acquired but unsaved payload until an atomic, verified handoff or explicit discard. It tracks operation identity and a captured actor, workspace, normalized API origin and job; it never uses the currently selected workspace to infer the origin of an older callback.
2. Separate **editing**, **transfer in progress**, **bytes acquired but not saved**, **saved on phone**, **sync pending**, **failed** and **server-confirmed**. While bytes are only in memory, say so and never imply they will survive process termination. If protection, disk or durable handoff fails, retain the in-memory work while the process lives and provide retry and deliberate discard. Do not promise survival of device termination or OS eviction while no durable write is possible.
3. Persist note drafts and acquired media before claiming local save. Use an atomic protected actor/workspace/origin/job-bound unit with stable identity, an explicit schema/version, strict decoding, backup exclusion and bounded size. Avoid copying or promoting an unscoped legacy item to a guessed identity. The existing protected `PendingMediaStore` can own successful normal handoffs; separately design a recoverable **original-owner** staging path for a callback whose session has since changed, since its current context guard rightly rejects that callback. Never upload a staged item until current server authority is verified for its original job.
4. An account/workspace switch or session expiry immediately hides and prevents edits/uploads to former-owner data, but does not discard it. A later verified same-owner session may offer explicit recovery after either a fresh authorized job/capability check or a separately qualified, unexpired per-job offline authority contract. Do not turn previously supported offline work into an unconditional online-only flow. No such offline contract is currently qualified for this path, so cold-offline recovery remains held until it exists. Avoid making a client-side ownership record proof of server authorization. A changed actor, organization, origin, job, authority epoch or unsupported expiry must not expose or submit the old work.
5. Capture/import initiation and nonempty note changes invalidate the shared review state before any asynchronous work. The sign-out warning must account for active transfers, unsaved memory-only work, protected staging and durable queued items. It must be paired with the exact confirmation/revalidation contract in `2026-10-29-signout-saved-work.md`; an invalidation alone is not an authorization to delete. Cancellation must leave operations and work usable. A session transition while a platform picker is presented must not silently destroy already acquired bytes.
6. Sign-out, explicit discard, crash/relaunch, storage failure and authentication expiry have different semantics. Define and test the privacy/retention decision before changing the current sign-out deletion policy. If a user explicitly discards, delete only the exact selected work and report deletion failure. Do not automatically discard other workspaces, legacy data or a newer revision.
7. Preserve full note text and original acquisition metadata. A save completion may clear the editor only if it still matches the exact submitted revision; newer edits must remain. Do not auto-retry an uncertain online note through the existing non-idempotent REST fallback; its separate server receipt/idempotency work is still held.
8. A confirmed sign-out must have a terminal, operation-specific decision for each outstanding picker/camera/scanner/import. Do not clear confirmed device work while an unresolved operation can still produce bytes; either let it reach a reviewed durable state, or explicitly explain and obtain the user's choice to cancel/discard that operation. A terminal decision or tombstone must prevent a late callback from silently recreating original-owner files after confirmed deletion. If cancellation cannot guarantee the platform callback has stopped, keep sign-out pending or re-present a truthful recovery choice; never silently drop newly acquired bytes. Scope tombstones to the exact operation and generation so they cannot discard a newer capture.
9. Record every note edit synchronously in the coordinator's owner-bound in-memory revision before publishing it; a copy only on disappearance or after a debounce can lose the last keystroke. Durable writes may be scheduled separately, but failure or pending persistence must remain visible. Identify concurrent editors by scene and editor ID, and define explicit conflict/recovery behavior instead of silently overwriting a second window's draft.
10. Bound acquisition before loading large payloads into memory and bound simultaneous imports. The current picker loads a whole `Data` before the 8 MB check; design a supported file-backed or streaming acquisition, bounded protected staging and memory-pressure handling before relying on it. The app cannot guarantee that iOS will deliver an unfinished camera/picker callback after presentation dismissal or process termination. Preserve bytes once actually acquired; truthfully mark or cancel unfinished platform operations and verify lifecycle behavior on a device.
11. Apply the same preservation decision to workspace switching and session transitions, not only sign-out. `WorkspaceGateView` currently dismisses after awaiting `selectOrganization` without an explicit success result. An aborted or failed switch must keep recovery reachable and restore push registration or surface a truthful recovery state if unbind already occurred.

## Implementation sequence

1. Specify a root-owned coordinator and storage contract, with deterministic owner/job keys, capture operation IDs, revisions, lifetime rules and recovery UI. Identify all camera, scanner, photo picker, file-import, note and navigation exit paths. Design interactions with the gate and sign-out coordinator before adding warnings.
2. Add real-file tests before storage code: exact owner/origin isolation, same-owner rebind after expiry, foreign-owner denial, corrupt/unreadable/protected data, interrupted atomic writes, failed cleanup and disk-full behavior. Verify existing pending media and legacy files are preserved. Keep payload bytes and note bodies out of test logs.
3. Move the note draft to the coordinator and wire editing, navigation, success, retry and conditional clearing. Test the final keystroke during invalidation, concurrent scenes editing the same job, typing after a request starts, delayed success/error, workspace/session switch, cancellation and relaunch with long text. Confirm no new note appears in a different workspace.
4. Move photo-picker transfer and camera/scanner/import callbacks into the coordinator. Retain captured bytes under the original operation scope across view disappearance and session change, and durably hand off or show a truthful memory-only recovery state. Test delayed callbacks, oversized inputs before full materialization, bounded concurrent imports, memory pressure, a failed protected write, repeated picker selection, context changes, cancellation, session expiry and process restart where bytes were durably saved. Exercise late success after an explicit discard/sign-out decision and verify it neither silently recreates files nor destroys unreviewed acquired bytes. Exercise real iPhone camera, scanner and privacy settings separately from simulator tests; do not assume an OS callback survives dismissal or termination.
5. Integrate the coordinator with the warning-time proof and final coordinated sign-out or workspace-switch decision. Test work acquired before confirmation and while unbind or inventory scan is awaiting, including equal-count replacements, multiple windows, cancellation, retry, changed session, aborted switch presentation, and push re-registration on abort. Prevent reentrant deletion and preserve inaccessible work.
6. Independently review identity, privacy, storage, pending transfer cancellation, user-visible loss states, long text and accessibility. Verify on phone and iPad, include exact UI and persistence evidence, and update release notes only after a qualified increment. Do not upload this work while the existing delayed-unbind loss test fails or the deletion boundary is unproven.
