Events targeting the current job or invoice show details rather than push a duplicate screen. Details are snapshots scoped to the current actor, workspace, owner, session and authority revision.

Outbox follow-up in uncommitted WIP: local enqueue writes before reporting success, preserves an unreadable queue, and keeps the note text with an inline save failure. Scoped admission rejects a stale actor/workspace binding; job and schedule actions also check session, authority and API epochs after network responses. The onboarding sign-out routes now show the saved-work warning. The focused queue, onboarding and activity selection run passed 34 tests (`/private/tmp/thorbis-outbox-review-final.xcresult`); it did not test a delayed network response through the UI.

Independent review found that retry did not reload a queue after protected storage became readable, and that saved work can change after the warning while sign-out awaits device unbind. The real context-bound retry test reproduced the first issue (`/private/tmp/thorbis-outbox-retry-red.log`); this run was interrupted after the test reported its expected failure while Xcode was finishing cleanup. The retry fix passed all 27 focused queue tests (`/private/tmp/thorbis-outbox-retry-final.xcresult`). The sign-out race remains unresolved: queue and media inventories both need an exact warning-time proof and revalidation or a safe freeze, plus reconfirmation when changed. A count-only check is insufficient, particularly for unreadable scopes. Do not release this WIP. Sync/dismiss persistence errors, non-idempotent note REST fallback, cold-offline authorization, actual delayed-response UI journeys, and accessible/device sign-out verification also remain open.

Further review identified missing-file retry and initial-load ownership gaps. The first two new filesystem regressions failed against the previous WIP (`/private/tmp/thorbis-outbox-absence-owner-red.log`; cleanup was interrupted after test output). Initial load and retry now validate every entry's actor and workspace, and only a POSIX `ENOENT` permits treating a missing queue as empty. The final focused queue suite passed 31 of 31 tests (`/private/tmp/thorbis-outbox-absence-owner-final2.xcresult`), including a non-file path and separate foreign-actor and foreign-workspace cases. The holds above remain unchanged.

The sign-out loss was reproduced using a real temporary outbox and media store with a delayed `onWillUnbindDevice`: after sign-out began and while unbind was pending, a note and photo were saved, then both were cleared when sign-out resumed. The intentionally failing regression is `SessionControllerTests.testSignOutDoesNotEraseNewSavedWorkWhileDeviceUnbindIsAwaiting`; `/private/tmp/thorbis-signout-race-red.log` records four expected assertion failures, after which Xcode's stuck post-test cleanup was interrupted. No sign-out runtime fix is claimed.

The warning-time proof must cover all queue files and both scoped and legacy media, including unreadable files and changes during any asynchronous scan; counts and in-memory epochs alone cannot prove an unchanged filesystem. Media can contain many large payloads, so hashing them synchronously on the main actor is not acceptable. A final recheck must have no suspension before deletion, must fail closed when a scope cannot be verified, and must trigger a new warning and confirmation rather than delete changed work. Since unbind may already unregister the device, an aborted sign-out also needs push registration restored or a clearly surfaced recovery state. The four sign-out entry points must share this contract and support cancellation. Keeping all files silently is not an established substitute: the current policy explicitly deletes device copies, the outbox does not include origin in its scope, and older media is unscoped. The intentionally failing regression and remaining holds keep this branch out of release until the architecture and recovery are verified. A concrete redesign and verification plan is in `docs/superpowers/plans/2026-10-29-signout-saved-work.md`.

An unconnected inventory prototype now hashes file contents in bounded chunks off the main actor, uses no-follow descriptor-relative traversal with nonblocking opens, rejects unsupported paths and verifies previously observed metadata after the scan. Seven focused simulator cases passed (`/private/tmp/thorbis-inventory-midscan-green.xcresult`), including a deterministic file change after its scan, static links/FIFO, a symlink ancestor and the simulator's actual Application Support directory. The corresponding mid-scan test failed before revalidation (`/private/tmp/thorbis-inventory-midscan-red.log`). This prototype does not lock files or coordinate with the stores; another change can occur after its final observation or before deletion. It must not authorize sign-out. Deterministic path-swap tests, physical-device path support, responsiveness at scale, push recovery and the actual delayed-unbind regression remain unqualified. The runtime sign-out path remains unchanged.

An unconnected shared mutation-gate prototype now gives a review a one-use ticket and invalidates it on queue or media mutation attempts. Cancellation invalidates its ticket without blocking subsequent work. The first queue, media and cancellation cases failed against the scaffold (`/private/tmp/thorbis-savedwork-gate-red.log`); the focused queue, media, legacy recovery and gate suite later passed 73 tests with one simulator-only protection skip (`/private/tmp/thorbis-savedwork-gate-final.xcresult`). Additional gated-request tests exercise queue and media completion after a review starts. Mutation coverage still needs independent review, and the gate cannot detect external filesystem writes or establish the final scan-to-delete boundary. Sign-out does not use it; the delayed-unbind data-loss regression remains intentionally failing. Push restoration, durable sync/dismiss semantics, media and queue deletion failures, and device qualification remain open.

Review found reentrant mutations inside the prototype's synchronous check could incorrectly report success. Real queue admission, queue clearing and media admission tests reproduced it (`/private/tmp/thorbis-savedwork-reentrant-red.log`); the gate now rejects those nested mutation attempts, preserving saved entries and returning failure. It deliberately has no authorized deletion path: current `clearAll` cannot verify successful removal. A redundant same-identity queue bind also unnecessarily invalidated reviews; that regression failed before the no-op check moved ahead of invalidation (`/private/tmp/thorbis-savedwork-rebind-red.log`). The latest focused run passed 77 tests with one simulator-only file-protection skip (`/private/tmp/thorbis-savedwork-review-final.xcresult`). These changes require another independent review. Unsaved typed notes and pending picker/camera data are not included in the gate, and conservative media reload invalidation could make reconfirmation repetitive; neither issue is qualified. The gate is not wired to sign-out and cannot replace coordinated external filesystem proof, fallible deletion, or push recovery.

Independent follow-up review found no new material blocker to preserving this narrow gate strictly as unconnected WIP; the reviewer did not run tests. Existing `clearAll` cannot run inside the check, and a true check result is not evidence of successful removal. The untested captured-work, external-change, deletion and push holds remain unchanged.

Typed job notes and pre-save media cannot be protected by adding a warning counter: the note is owned by a job view that is destroyed on session-generation changes, and selected media bytes are cleared on view disappearance while platform callbacks can remain in flight. The independently reviewed preparation plan is `docs/superpowers/plans/2026-10-29-captured-work-signout.md`; it includes original-owner preservation, bounded acquisition, final-keystroke and multiwindow handling, terminal late-callback decisions, session/workspace-switch recovery, and a qualified offline-authority dependency. No implementation or preservation claim is made, and the existing sign-out loss regression remains failing.

No editor, media, gate, session or sign-out flow uses the prototype; it does not preserve actual user work and must not be released as such.

Independent re-review found no new concrete blocker to preserving the revised prototype only as unconnected, memory-only WIP; the reviewer did not run tests. The method that begins a verified session does not itself verify authority: any eventual integration must invoke it synchronously from the current `SessionController` actor/workspace/origin/generation/authority event, never from a late callback.
