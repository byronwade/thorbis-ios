# Price book presentation

The standalone price book follows Paper artboard VSA-0: loaded items are grouped by their actual material/service kind, with short names, units and aligned prices. Groups can collapse; search or a selected category reveals matching groups. Counts say “loaded” while there is a next page. There is no separate name, category or photo in the current list contract. The presentation derives a concise title from the canonical description and removes only the exact known demo reconciliation suffix from ordinary display. Full meaningful text remains available. Editing and stored-text copying retain the original string, including that suffix; arbitrary bracketed text is not stripped.

The server detail route requires edit access. A staff member without that access can open a local detail using only fields already visible in the list. Its presentation closes on session, workspace, actor, authority or view-permission changes. On an authority revision with the same actor, workspace, origin and session, already-loaded list rows remain visible as previously loaded and retain their pagination cursor; the new local detail is unavailable until a successful refresh. Loading another page appends to the existing list. A refresh that promotes old rows to a new authority explicitly bypasses the local HTTP cache; a failed refresh leaves existing pages intact. Revocation of view permission and identity or workspace changes hide the list.

This preserves the existing list's offline behavior, but same-owner visibility after a grant narrows while retaining view permission was already a list authorization limitation. Identity and capability alone do not prove resource grants are unchanged. A trustworthy server-provided authorization scope or a separately specified offline policy is needed to resolve that limitation; this change does not claim to resolve it. Do not interpret the stale notice as authorization of previously loaded data under a new grant.

Simulator captures and test results are retained in the local task's temporary artifacts. Physical-device accessibility and actual offline behavior remain to be checked; the failed-fetch fixture models a server error, not an actual disconnected network. Debug preview fixtures must not appear in release builds.
