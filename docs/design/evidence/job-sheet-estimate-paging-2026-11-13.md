# Technician job estimate paging — 13 November 2026

Candidate based on release `66caf2e3`: the job sheet requests one estimate membership page initially and continues only when Load more is selected. Rows are scoped to the current job, actor, workspace, API origin and authority. Incomplete scans are not used as complete totals or to satisfy creation/decision gates. Creation explicitly reads the full fresh job set when requested; that separate read does not replace the paged list. Transient failures retain only same-scope known rows as stale; denied or retired authority clears them. Detail failures offer a full refresh, while an interrupted page retries the cursor.

`job-sheet-paging-1113-retry.log` built the candidate and ran ten focused simulator model cases and one technician Add estimate UI case. Nine model cases passed; the offline-retention test failed because the fixture had not seeded the membership copy. The Add estimate UI case passed, but the combined xcodebuild exited 65. A subsequent isolated rerun `job-sheet-offline-retry-1113.log` seeded the scoped membership copy while deliberately removing its detail copy, and passed that case (1 test, zero failures, exit 0). No production code changed between the two runs. The loader and page adapter host probes and Swift syntax/diff checks passed.

The tests do not establish live-server performance, all job entry points, broader offline/permission behavior, VoiceOver, a full app test suite, or TestFlight availability. This candidate is not a release. Independent review and merged-tree verification are still required.
