# Price book progressive first results

The technician opens the estimate or invoice item picker and needs an item while the catalog is loading. The API's current collection endpoint supplies cursor pages but no equivalent ranked fuzzy-search contract. Downloading every page remains necessary for the current complete offline catalog and whole-book fuzzy/frecency search; this change must not be called server-side search or demand loading.

When there is no complete saved snapshot, publish the first page in the current actor/session/API scope while fetching the remaining pages, then publish the complete snapshot. This avoids rebuilding the full search index on every page. Explicitly identify partial results, counts and failures in the picker. Never write partial data as the complete offline snapshot. If a nonempty complete snapshot exists, continue displaying it until a replacement has completely loaded. An empty complete snapshot stays on disk while a clearly labeled first page is shown. Cancel or discard results after an organization, session or API generation change. Keep the existing local fuzzy ranking, selection, favorites and retry paths.

Acceptance: a gated second-page test proves the first page is usable before the later page returns; interrupted load cannot overwrite a complete cache or pretend to be complete; stale requests never publish into another scope; UI labels incomplete results and retry accurately. Run focused catalog/search and picker tests with representative paging; verify visible partial/error states, accessibility and release behavior before claiming completion. A bounded server search needs an authorized, tenant-scoped ranked query, stable cursor/snapshot semantics and a contract matching local fuzzy matching, filters and pricing; partial online results cannot replace the offline snapshot.

## Evidence

- The first-page regression failed on the base implementation: the catalog was empty while the second response was held. With this change, the gated response test passes and proves partial pages are not written as a complete cache.
- The focused run on iPhone 17 Pro simulator passed 29 catalog/search tests and two picker tests, including selecting a loaded item, incomplete search messaging and searching the later page after completion. The screenshot run passed the partial picker test with retained images: [loaded](pricebook-partial-loading.png), [search](pricebook-partial-search.png).
- An initial UI run failed because it inherited an earlier preview's complete sample cache; the explicit DEBUG-only partial fixture now clears only that fixed sample cache before starting. The corrected run passed. No production cache is cleared by that fixture.
- The existing complete-cache retention and scope-switch regression tests passed. No device profiling, iPad, VoiceOver or true bounded server-side search has been verified; every catalog page still loads in the background to retain the existing complete offline search behavior.

- The earlier scope/cache regression run passed 35 catalog/search tests and both picker UI checks (`/private/tmp/thorbis-pb-origin-green.log`). Independent review then found that origin alone did not establish actor or policy scope, and that a complete snapshot remained selectable immediately after API invalidation. The new regression run reproduced both failures before the follow-up fix (`/private/tmp/thorbis-pb-actor-red.log`).
- Partial publication is limited to the first page until completion. This reduces repeated indexing, but it is still a full background download and is not a measured performance claim. Page anchoring uses the first visible page item's ID when complete ranking arrives; exact scroll position within the page is not preserved. The ID lookup does not modify the query or selected draft items.
- Latest source verification: 36 catalog/search tests and both picker UI tests passed on the dedicated iPhone 17 Pro simulator (`/private/tmp/thorbis-pb-anchor-green.log`; xcresult `Test-Thorbis-2026.11.02_19-46-36--0500.xcresult`). The anchor unit regression verifies the same item remains within the newly ranked page and respects filters/exclusions. The UI tests do not simulate a multi-page partial-to-complete transition, so that specific interaction and exact scroll position remain unverified.

- The version 2 cache envelope now binds the normalized origin, organization filename, verified actor, policy version and server authority generation. The verified session snapshot stores the origin and generation in device-only Keychain; a legacy snapshot can still restore the existing session but cannot unlock an old unscoped price book. After upgrade an online authority refresh and complete catalog refresh are needed before this cache is available offline. A matching actor/policy/generation can reuse its complete cache after offline relaunch even though the local authority revision changes. One organization file is retained, so switching actor or origin can replace the other scope's offline copy.
- Earlier scoped-cache run passed 51 catalog, search and offline-session tests plus two picker UI tests (`/private/tmp/thorbis-pb-authority-final.log`; xcresult `Test-Thorbis-2026.11.02_20-00-13--0500.xcresult`). Tests cover changed actor, policy and API generation, server-authority revalidation, legacy snapshot, wrong origin and matching-scope offline relaunch. The tap handler rechecks current capability and authority expiry; an expiry-during-tap UI test is not included. The backend source contract binds its generation to actor, policy and scope, with price-book rows organization-scoped and narrower scopes empty. Deployed migrations and every possible policy mutation were not verified.

- After independent review, a definitive 4xx response (except timeout/rate limiting) hides complete and partial items, blocks selection and records a scope-bound device-only Keychain denial marker before attempting file removal. A completed authorized refresh must atomically save its replacement before clearing the marker. A test forces file deletion to fail and verifies that the marker blocks an offline relaunch; another verifies recovery. Marker-write failure with successful deletion and the combined failure are also injected. If both persistent operations fail, selection remains blocked for that scope in the current process, including across session changes, and the app warns; an offline process after a restart cannot discover an event that neither store recorded. That cross-restart condition remains unresolved.
- The signed simulator Keychain diagnostic passed read/add/delete (`/private/tmp/thorbis-pb-keychain-signed.log`). The unsigned test host returned `-34018` (missing entitlement); it was not treated as item-not-found. One attempted pre-fix marker test did not execute because of a simulator Mach IPC failure (`/private/tmp/thorbis-pb-denial-marker-red.log`); the initial denial and same-process scope regressions were observed failing before their respective fixes. The final signed exact-source run passed 84 catalog/search/session tests and two picker UI tests (`/private/tmp/thorbis-pb-signed-scope-final.log`; xcresult `Test-Thorbis-2026.11.02_20-28-27--0500.xcresult`). Device Keychain and an expiry-during-tap UI interaction have not been separately qualified.
