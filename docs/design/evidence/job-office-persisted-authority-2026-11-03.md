# Held persisted authority helper

The unexposed helper rereads the session snapshot outside SwiftUI rendering and compares actor, workspace, normalized origin, policy, authority generation, capabilities and features with the currently verified session. It returns a deadline no later than either the current or persisted session/authority expiry. An absent, mismatched or expired snapshot fails closed. It does not establish job-specific access or offline revocation, and callers must check current runtime identity again after asynchronous operations.

Three focused tests passed (`/private/tmp/thorbis-office-authority-green.log`, `/private/tmp/thorbis-owner-ui-derived/Logs/Test/Test-Thorbis-2026.11.03_12-38-17--0500.xcresult`; hashes `/private/tmp/thorbis-office-authority-green-manifest.txt`). They cover a dropped save, mismatch/origin/expiry, and offline restoration into a new SessionController using an in-memory snapshot store. This is not real Keychain or process-relaunch evidence. Before implementation, a nil-returning scaffold produced the expected failing assertion (`/private/tmp/thorbis-office-authority-assertion-red.log`).

Open question: SessionSnapshot currently does not bind a server session ID. A stale persisted snapshot with the same actor/workspace/policy/grants could match a later live login after a failed Keychain write. The helper must not be integrated as exact-session proof until that is resolved. Logout fencing, real Keychain failures, clock rollback, job-specific authorization, store integration and signed-device testing remain unverified. Keep this candidate held.

## Exact session binding follow-up

A focused test reproduced the stale-session risk: the helper accepted an old persisted session after a new login with the same actor/workspace/policy/grants when the new snapshot save failed (`/private/tmp/thorbis-office-session-id-red.log`). The follow-up hashes the optional server session ID and stores only that digest with the session snapshot; a missing or legacy digest cannot authorize the cold office cache. The helper requires the digest to match the current authenticated session, and returns it to a future scoped store. DEBUG Paper preview supplies a synthetic session ID.

Four focused simulator tests passed (`/private/tmp/thorbis-office-session-id-green.log`, `/private/tmp/thorbis-owner-ui-derived/Logs/Test/Test-Thorbis-2026.11.03_12-43-28--0500.xcresult`); source hashes `/private/tmp/thorbis-office-session-id-green-manifest.txt` matched after the run. The tests use in-memory snapshot storage; actual Keychain persistence, stable/non-bearer session-ID behavior in the deployed auth response, session rotation, cross-process logout fencing and integrated cold offline remain unverified. The helper is not wired to a production screen or shipped.
