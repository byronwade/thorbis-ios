# Invoice line keyboard and close control

The existing price-book workflow reproduced a failure on unmodified release source `a1e05a4`: after entering a quantity with the number keyboard up, tapping the expanded line's Done did not close it. The simulator recording showed the line's Done button covered by the floating keyboard Done control. The invoice action bar also reduced the available space. The revised editor temporarily hides its commit bar while the keyboard is up, reserves additional scroll clearance, dismisses focus when closing a line, and formats a valid focused price before removing its field. Invalid or incomplete text is not converted.

On the revised product source, a targeted iPhone 17 Pro simulator run passed both the original direct catalog/Close line interaction (including non-overlap checks for the keyboard, keyboard Done and invoice action bar, plus keyboard dismissal and restored Save/Issue actions) and a focused-price case confirming `12.5` becomes `12.50` after close and reopen. Result bundle: `/tmp/thorbis-close149-derived/Logs/Test/Test-Thorbis-2026.11.02_22-35-48--0500.xcresult`.

A subsequent full focused run passed all 13 invoice editor unit tests, including incomplete and negative price cases, and four UI cases: focused-price formatting, largest text, repeated adds and custom item. Its first direct-interaction case encountered repeated XCTest animation-idle waits and ended with a runner restart; Xcode reported the overall run failed. The result bundle labels that case `Test crashed with signal term` and also includes the warning `Invalid frame dimension (negative or non-finite)`. The cause was not established. Result bundle: `/tmp/thorbis-close149-derived/Logs/Test/Test-Thorbis-2026.11.02_22-42-38--0500.xcresult`.

The largest-text test now explicitly scrolls until the catalog row's tap point is above the fixed Done bar, rather than trusting XCTest's `isHittable` on a partly obscured row. The selected case passed in that full run; the test's attached screenshots show the added line and invoice actions. A previous run failed because a partially visible catalog item reported hittable while its center was under the fixed bar. This is an accessibility reachability limitation: at the largest text size the technician must scroll to the item.

These are simulator observations. Physical iPhone, iPad floating/split keyboards, hardware keyboards, and other text sizes have not been verified. No TestFlight deployment is implied by this branch or evidence.
