# Job estimate membership paging prototype — 13 November 2026

This is an isolated, **unwired** coordinator, not user-facing paging. It permits one job-link page per explicit request, rejects foreign job links, duplicate link IDs, repeated/empty cursors and retired authority, and deduplicates estimate IDs. Network failure leaves the current cursor retryable. `scanUsedOnlyFreshResponses` requires the caller to provide an independently verified provenance for each page. An exhausted cursor is not a frozen server snapshot; approval must separately revalidate each selected estimate's job association and issued revision.

Host command:

```sh
swiftc -swift-version 6 -parse-as-library Thorbis/Sources/JobEstimateMembershipPager.swift scripts/tests/job_estimate_membership_pager_host.swift -o /private/tmp/job-estimate-membership-probe && /private/tmp/job-estimate-membership-probe
```

The synthetic host probe passes single-demand paging, scope retirement after await, foreign job rejection, unverified saved-page gating, cursor-loop rejection, failed-page retry, duplicate estimate IDs and concurrent invocation. The initial test-first compilation failed because the type/file was not yet present; it was a compile failure, not a demonstrated production behavior failure.

A real one-page API adapter and two URLProtocol tests are prepared, but not built or run. The adapter records response provenance and checks origin, request generation and saved-copy scope revision around the request. Its default non-fresh mode retains the existing saved-copy path; callers must explicitly require a fresh read for a current-response claim. UUID-like identity and cursor comparisons normalize letter case.

Not established: real API adapter / URLSession response provenance, iOS compilation or UI, saved-copy behavior, mutation across pages, exact approval membership/revision revalidation, accessibility, a Load more action, or actual memory/network measurements. This does not address invoice paging. The existing production handoff continues to load all link pages and estimate details. No feature or performance claim is made from this probe. Do not expose this coordinator or use it to enable approval without those integration checks.

Independent review found that a completed scan cannot establish current authority or a stable membership snapshot. The API now names its properties as historical scan facts, and a host check shows subsequent operations reject retired authority even though those historical facts remain true. Identity comparison for links, estimate IDs and cursors is case-insensitive; a host regression failed before this change and passed afterward. The page adapter requires an explicit current-authority closure instead of defaulting to true.

Additional URLProtocol test source covers cursor-scoped saved pages, denying fresh use of offline copies, 403 propagation, and authority retirement while a request is in flight. These tests have only been parsed and have not been run in iOS/Xcode. They do not replace a real server snapshot, selected-membership revalidation or a user-facing page flow.

The extracted production page adapter also passed `python3 scripts/tests/test_job_estimate_page_adapter_host.py`, which uses a host stub to check one request, cursor forwarding, saved-response provenance, normalized origin comparison and scope-revision change after an await. This probe was added after the adapter, so it was not a test-first red, and it does not execute URLSession, the database or SwiftUI.

The canonical current jobs repository orders link UUIDs descending and emits the last returned link ID as its next cursor (`domains/jobs/src/persistence/repository.ts`, `packages/validation/src/pagination.ts`). The prototype now rejects a cursor that does not identify the last returned link; a host regression failed before the check and passed afterwards. This validation depends on that current server contract and must be revisited if the API adopts opaque cursors.

## Concrete handoff integration still required

1. On `JobEstimateHandoffModel.refresh`, obtain a fresh job and bind a new page coordinator to the same job, actor, organization, API origin, session generation, authority revision and saved-copy scope. Reset it whenever that authority changes. Treat `scanReachedEnd` and `scanUsedOnlyFreshResponses` solely as historical facts, never as current authorization or a frozen list.
2. Read only the first membership page through `fieldJobEstimateLinkPage`, merge the job's origin estimate ID once, and load only those details with bounded concurrency and per-response provenance. Publish a partial list explicitly; keep previously selected IDs until a current full reconciliation. On transient errors retain safely scoped readable copies as stale, hide denied/foreign results, and show a retry.
3. Give the customer an accessible **Load more estimates** control, and optionally request a page when its last visible row is reached. Never start a second request for the same cursor; validate scope before and after each await. Retry only the failed cursor, preserving displayed cards and selection. Explain that the list is incomplete without reporting an exact total.
4. `JobEstimateHandoffModel.canReview`, `detailsCurrent`, and `approvalAllowed` currently require the complete job list. Keep complete-set review/approval gated until the membership scan reaches the end with verified fresh pages and all needed detail results; keep individual selected terms/revision verification in `verifyMembership`/`issuedDetails`. Their existing full fresh membership equality check remains mandatory, because pagination is not a server snapshot and links can change between pages. Reconcile selected IDs only after an authoritative full scan. Ensure neither a cached page nor a failed detail can turn the set complete.
5. Preserve the existing saved-copy behavior for field browsing. An offline page can be read with explicit stale status, but it cannot prove current membership or authorize a signature. Verify scoped page keys and continuation copies across restart/authority changes; do not silently introduce online-only requirements for workflows that already support offline reads.
6. Test real URLSession cursor/provenance and cache behavior, 40+ records, no later requests before user demand, out-of-order details, retry/cancellation/supersession, insert/delete between pages, actor/workspace/permission retirement, cursor loops, selected-ID retention and actual signing guards. Test VoiceOver, large text and iPad. Measure request count and time-to-first-content, rather than equating lazy rendering with network paging.

The coordinator and page adapter are intentionally not wired into `JobEstimateHandoffModel` or the UI. This plan is not evidence that they work together; no current customer experience or build has changed.
