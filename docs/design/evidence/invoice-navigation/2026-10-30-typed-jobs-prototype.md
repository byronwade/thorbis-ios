# Typed Jobs navigation prototype — held

This is an experimental, DEBUG-only implementation of the phone Jobs stack, activated only by `--paper-preview --invoice-route-owner-experiment`. It is not enabled for real users and does not fix production navigation. Do not cherry-pick or release this checkpoint without the route-parity and payment-identity tests in the implementation plan.

The Jobs stack owns a typed route array and receives native NavigationLink values through a compatibility wrapper. A completed single top invoice pop emits the captured route. The job view hides the prior invoice's payment action, refreshes complete job-scoped invoices and the exact returned payment model, and permits collection only for the verified returned invoice and current session context. Existing roots retain their NavigationPath storage, though the compatibility wrapper touches value links used by those roots and therefore requires full navigation and accessibility regression testing.

New UI tests retain the equal-balance identity assertions and check that returning from a paid document does not make another invoice collectible. These tests have not been run. There is no evidence yet that the route change avoids the SwiftUI idle loop, that path-binding event delivery is reliable for native Back, swipe-back cancellation, VoiceOver and hardware keyboards, or that the mutable job view remains alive while a route is popped. iPad, custom tabs, schedule, deep links, sheet-launched jobs, other route destinations, slow/failed refresh, authority changes, and explicit deposit/collection actions require exact-source tests. In particular, root-level preview and deep-link path append sites need a complete migration before this flag can become a production feature.

The caller still owns server membership and payment authorization checks. Completion, partial reads, route cancellation, overlapping requests, refresh failure, real network and user interaction must be independently validated before integration.
