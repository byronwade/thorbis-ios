# Typed Jobs navigation prototype — held

This is an experimental, DEBUG-only implementation of the phone Jobs stack, activated only by `--paper-preview --invoice-route-owner-experiment`. It is not enabled for real users and does not fix production navigation. Do not cherry-pick or release this checkpoint without the route-parity and payment-identity tests in the implementation plan.

The Jobs stack owns a typed route array and receives native NavigationLink values through a compatibility wrapper. A completed single top invoice pop emits the captured route. The job view hides the prior invoice's payment action, refreshes complete job-scoped invoices and the exact returned payment model, and permits collection only for the verified returned invoice and current session context. Existing roots retain their NavigationPath storage, though the compatibility wrapper touches value links used by those roots and therefore requires full navigation and accessibility regression testing.

New UI tests retain the equal-balance identity assertions and check that returning from a paid document does not make another invoice collectible. These tests have not been run. There is no evidence yet that the route change avoids the SwiftUI idle loop, that path-binding event delivery is reliable for native Back, swipe-back cancellation, VoiceOver and hardware keyboards, or that the mutable job view remains alive while a route is popped. iPad, custom tabs, schedule, deep links, sheet-launched jobs, other route destinations, slow/failed refresh, authority changes, and explicit deposit/collection actions require exact-source tests. In particular, root-level preview and deep-link path append sites need a complete migration before this flag can become a production feature.

The caller still owns server membership and payment authorization checks. Completion, partial reads, route cancellation, overlapping requests, refresh failure, real network and user interaction must be independently validated before integration.

Touch-only evidence on e55fb6e: the iOS 18.2 simulator `Thorbis Narrow Customer Clarity` passed all three flagged UI tests in `/private/tmp/thorbis-typed-jobs-ui-e55.xcresult`: both scoped invoices opened, returning from the paid invoice did not expose collection of another invoice, and returning from INV-2209 in the equal-balance scenario opened collection for INV-2209. The test run did not exercise VoiceOver, keyboard, interactive-pop cancellation, real server data, other roots or route parity. This evidence does not qualify the prototype for release.

On the subsequent identity-scope candidate, `/private/tmp/thorbis-typed-identity-regressions.xcresult` passed four iOS unit-test suites and seven sequential UI tests on the iOS 18.2 simulator. The UI tests covered opening both invoices, equal-balance identity, paid-return safety, a returned invoice later becoming paid while another remains owed, changed balance, API invalidation, and same-actor authority revalidation. Unit tests cover per-presentation identity, route context and pending-pop expiration. Debug-only controls triggered the authority, API and invoice-state changes; no real server transaction was exercised.

The earlier `/private/tmp/thorbis-typed-jobs-parity.xcresult` passed Jobs-to-customer-to-new-job-sheet navigation and an edge drag that left the invoice detail visible before native Back; those results predate the identity-scope candidate, and the edge drag alone does not prove UIKit began an interactive-pop transition. Neither result verifies actual VoiceOver, keyboard, completed swipe, all other app roots, concurrent real-network changes, route parity, or a production build. The typed stack remains debug-gated and held.

The DEBUG-gated phone Schedule stack subsequently adopted a separate typed path and owner, including its requested-job/deep-link entry. `/private/tmp/thorbis-typed-schedule-route.xcresult` passed the Schedule requested-job equal-balance scenario and the existing typed Jobs equal-balance scenario on iOS 18.2. This is touch-only preview evidence and does not cover normal Schedule list navigation, tablet, sheet-created jobs, custom tabs, actual VoiceOver or real-server behavior.
