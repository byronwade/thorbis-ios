# Invoice navigation investigation, October 30

This is diagnostic evidence, not a release fix. On base 68a7aa7, programmatic invoice navigation can leave the UI thread busy in SwiftUI layout; destination lifecycle modifiers were implicated by controlled experiments. A plain direct NavigationLink opened invoice details without that stall, but it does not by itself preserve the selected invoice for subsequent collection.

An isolated experiment used `NavigationLink(destination:isActive:label:)` with a child-owned binding whose setter recorded the opened invoice ID, then attempted to restore it after the parent appeared. This initializer is deprecated. In `/private/tmp/thorbis-invoice-semantic2.log`, the job-invoice detail test passed, but the equal-balance selection test failed at `JobDocumentsUITests.swift:202`: after opening INV-2209 and returning, the collection sheet was not for INV-2209. A debug rerun, `/private/tmp/thorbis-invoice-semantic-probe.log`, reproduced the selection failure. The probe file in the iPhone 16 simulator app container contained only `parent appear opened=nil`; there was no activation binding setter event and no second parent onAppear event while opening and returning. The assumption that this binding catches semantic activation on the tested iOS 18.2 setup is false.

A later in-worktree draft that clears the old payment model and hides actions during refresh cannot work if the invoice ID was never captured. It is unverified and must not be integrated. A replacement needs a native semantic route whose identity is available for touch, VoiceOver, and keyboard activation; it must guard against presenting payment for another invoice during refresh, and must pass the opening and equal-balance collection regressions without hangs. The device was heavily contended during the probe; the actual UI assertions and probe file were produced, though the xcodebuild process lingered during final cleanup.

A diagnostic value-based NavigationLink with destination-builder side effects also failed the equal-balance test (`/private/tmp/thorbis-invoice-value-probe.log`). The following invoice tap waited for UI idleness while the destination builder ran hundreds of times. The test was intentionally terminated after the stall was observed. Destination-builder evaluation is not a reliable activation or pop callback and is not a release contract.

A separate exact isolation removed only the invoice destination's `onDisappear` from base 68a7aa7 while retaining the original programmatic route and selected-invoice assignment. In `/private/tmp/thorbis-invoice-programmatic-nodisappear.log`, INV-2209 opened but the equal-balance selected-collection assertion failed. The INV-2240 tap then waited more than a minute for app idleness, with the app observed at 100% CPU. The app process later disappeared without a final test result; the lingering runner was terminated. Removing the modifier alone is therefore not a qualified identity-safe fix.
