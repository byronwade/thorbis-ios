# Builder check — estimate editor/storefront

## 1. Approved-estimate canvas: incremental addition or edited replacement scope?

**Question needed before the C2/native implementation plan:** When an approved estimate is opened in the editable canvas, is its editable content only new incremental work, with accepted work retained as a separate immutable reference, or the entire desired resulting scope? In particular, what happens when the technician reduces/removes an already accepted line or changes its price?

**Why a wrong guess changes software:** Suppose the accepted source is two units at $100. The technician changes the displayed quantity to three. An incremental document containing three units bills $300 in addition to the original $200; an amendment derived from the resulting full scope adds only $100. A decrease to one unit requires a deduction/cancellation/credit authority rather than an ordinary positive addition. This determines editor seeding, request shape, accepted evidence, signed paper, invoice admission, and schedule/deposit handling. Keeping the original source immutable does not by itself choose these semantics.

**Existing evidence and proposed resolution:** `design-draft.md` “Lifecycle under the same surface” says approved edits seed a local change-order draft and saving creates/reuses a C2 addition, but does not define whether the edited lines are the increment or the resulting scope. The accepted `docs/superpowers/specs/2026-10-28-customer-addons-design.md` “Full customer add-on outcome” defines C2 as extras after original approval and bill-once accepted additions; `recon-backend.md` “Technician draft/revision and invoice boundaries” confirms approved revise is forbidden and existing billing admits the original source. Therefore the narrow source-backed resolution is an **addition-only draft with new incremental lines**, while the original accepted scope stays visible as immutable reference. Reducing/removing/repricing accepted work uses existing authorized correction/credit routes and is not synthesized by a cart or line copy. The coordinator can settle this explicitly in the design; no user approval menu is needed. If the intended outcome instead includes editing the full approved scope, the C2 spec needs an explicit amendment/delta and deduction authority before implementation can be concrete.
