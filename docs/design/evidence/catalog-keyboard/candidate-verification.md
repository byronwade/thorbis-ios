# Experimental catalog layout — not release ready

The candidate replaces the invoice search chip row with a labeled category menu, preserves the selected-line identity and quantity/price in its disclosure, places item price and Add before the complete description, and puts invoice page controls after the first match. Estimate pagination retains its original order. The large-text expanded invoice editor temporarily offers Results and Done; Results returns to the preserved query and category. All of this remains under review.

On the iPhone SE, `/private/tmp/picker-normal-final.log` shows seven presentation unit tests, estimate review, normal invoice quick-edit, repeated add, category/custom-line, multi-paragraph description and 73-match ordering passing. The same suite failed the estimate custom-line paging test after the paging change was initially applied to every caller; `/private/tmp/picker-estimate-order-retry.log` passed that test after limiting the ordering change to invoices. Normal screenshots `normal-repeat.png`, `long-description.png`, and `many-matches.png` are from the first suite; the later change affects estimate pagination only. They show the selected identity, price and Add above the keyboard for the short fixture; the complete long description is present in the accessible row and remains scrollable.

The largest-text header initially overlapped; `largest-text-header.png` shows the subsequent reflow with distinct controls. An early reflow also entered a SwiftUI layout loop when the focused field changed branches. Keeping the field in a stable branch removed that hang in `/private/tmp/picker-stable-focus.log`.

**Open:** the largest-text quick-edit test still fails while scrolling to unit price in `/private/tmp/picker-keyboard-geometry.log`; the disclosure can collapse or the control can fall outside the measured visible region. The preceding `/private/tmp/picker-direction-fix.log` failure screenshot shows the field visible even though the experimental helper overestimated a numeric keyboard's accessory height. The helper's geometry and scroll gestures still require verification, and the focused editor header has not been proven necessary or sufficient. Long-description real scroll/read, VoiceOver, iPad, localization, and physical device behavior remain unverified. The test fixture introduces debug-only description text that must be added to a release binary exclusion audit before any later archive.
