## Focus-aware prototype

The candidate tracks the selected quick editor's numeric focus and scrolls the complete field and label after focus and keyboard presentation. It clears the tracked target on disclosure collapse, selected-line change, and Done, and ignores keyboard notifications unless the same selected quick editor is expanded. This is limited to the accessibility-size added-line editor; ordinary invoice rows do not have the same focus callback.

`/private/tmp/picker-selectall-run.log` shows a fresh test passing with actual native Select All replacements from `1` to `10` and `245.00` to `275.00`, followed by return to results and refocusing search. `largest-text-quantity.png` and `largest-text-price.png` show the edited values and labels above the numeric keyboard. Earlier deletion and double-tap attempts failed to select the existing digit reliably; those failures are retained in `/private/tmp/picker-focus-guard-final.log` and earlier logs. The focused test is a single simulator run; physical-device, VoiceOver, iPad, localization and wider integrated-source testing remain open. A new assertion that the changed price remains in invoice review was added after this run and still needs execution.

## Focus-scroll follow-up (still failing)

An experimental guarded `ScrollViewReader` now tracks numeric focus only while the selected accessibility-size quick editor is expanded, clears it when that editor closes or selection changes, and targets the field with its label. The initial center-anchor run `/private/tmp/picker-selectall-run.log` passed actual replacements via native Select All, but consolidated run `/private/tmp/picker-b24-suite.log` later failed when the Select All menu was absent. Its recording showed the keyboard had disappeared after an interactive drag and part of the field was under the accessory.

The subsequent prototype uses a top anchor, disables interactive keyboard dismissal only while that editor is expanded, and strengthens the test to require a hittable numeric keyboard and entire field above its accessory after focus, without a post-focus drag. `/private/tmp/picker-keyboard-stable-run.log` still failed that 10-second check. `keyboard-disappeared.png` shows a focused field and Done accessory but no visible numeric keypad. The reason for the keyboard disappearance remains unproven; do not treat the focus-scroll prototype as verified. Standard invoice rows do not use this focus callback.

A full-height focused line editor for accessibility sizes is a possible next experiment because it could reduce nested-scroll and pinned-header pressure while retaining Results, saved query/category, immediate edits, description, quantity, price, reorder and delete. It must still demonstrate a stable keypad and post-focus visibility on an actual iPhone as well as the simulator; a sheet alone is not evidence of a fix. Reassess whether an extra presentation step is justified, and preserve all existing paths.

## Full-height line-details experiment (not release ready)

A native full-height sheet is now prototyped for accessibility-size editing of an added invoice line. It reuses the existing line editor and its description, quantity, price, ordering, delete and override-reason controls; Done returns to the retained search and category. The normal-size inline disclosure remains. The initial red test `/private/tmp/picker-sheet-red.log` correctly failed because the sheet did not yet exist. The prototype compiles, and `/private/tmp/picker-sheet-verify.log` reached the sheet and focused quantity but failed the strict post-focus keyboard visibility check before attempting either replacement. `sheet-keyboard-missing.png` shows a focused, visible quantity and price with only the Done accessory; no numeric keypad is visible. This repeats the keypad-disappearance symptom even in the sheet. Its cause is not proven; simulator configuration and physical-device behavior still require investigation. No successful quantity/price edit, query restoration, reorder/delete, override reason, or full-text/VoiceOver run has been verified for this sheet. Do not ship it on the strength of this experiment.

## Simulator software-keyboard comparison

On the dedicated Thorbis SE, the unmodified baseline preview was launched and its existing invoice quantity field focused. `baseline-keyboard-hidden.png` shows the focused field and Done accessory with no software keypad. Simulator → I/O → Keyboard → Toggle Software Keyboard was selected once while that field remained focused; `baseline-keyboard-shown.png` shows the numeric keypad afterward. No other device or global simulator service was changed. The menu did not expose the hardware-connection check state through the available accessibility tree, so this establishes a software-keyboard presentation setting, not its underlying hardware cause or a product fix.

With the software keypad shown, `/private/tmp/picker-sheet-keyboard-shown.log` reached the full-height sheet, passed post-focus keyboard visibility for quantity and unit price, and replaced the quantity using native Select All. It then failed before price replacement because Select All was absent for the long-press. `sheet-price-select-menu-missing.png` shows the price visible with a caret at its trailing edge and the numeric keypad visible. The current test's long-press target is near the right edge of the field; investigate whether it touches the value or its empty trailing boundary before interpreting the failure. Query/category restoration and actual price replacement remain unverified in this sheet. Preserve the original failed result and do not remove post-focus checks.

With the software keyboard explicitly shown, `/private/tmp/picker-value-target-run.log` retried the full-height candidate with the long-press moved from 96% to 90% of the price field width. The quantity replacement and both post-focus visibility checks passed, but Select All still did not appear for price; `sheet-price-target-retry.png` shows the unchanged price and visible keypad. The price edit and return-to-results assertion were not reached. A deterministic user-equivalent editing interaction and device testing remain necessary; a passing geometry check alone does not qualify the editor.

The bounded on-screen Delete experiment `/private/tmp/picker-keypad-replace-run.log` failed on its first tap: quantity remained `1`. `quantity-delete-stalled.png` shows the caret before the digit and the native Select / Select All menu visible. The test stopped before price editing and no data was saved. A follow-up test can use that visible Select All action as a person would, but must retain post-focus keyboard geometry, actual quantity and price replacement, and invoice-review persistence checks.

The native-menu follow-up `/private/tmp/picker-native-menu-run.log` timed out before replacement because the numeric keypad was again not visible after intervening simulator tests. `sheet-keyboard-hidden-again.png` captures the focused field with accessory only. The previous menu toggle was performed while the baseline preview was running and proved that the keypad could be shown for that session; it does not prove the setting persists across test sessions or simulator restarts. This run did not reach the Select All interaction. The simulator state must be checked immediately before a controlled comparison, and any explicit toggle during a test must be disclosed.
