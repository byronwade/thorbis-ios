# Stripe Terminal symbols: build 235

Xcode validated and uploaded Thorbis 1.0 (235) on November 12, 2026, with a warning that the StripeTerminal framework dSYM was missing. Upload success does not establish TestFlight processing or tester availability.

The device framework in the uploaded archive and the locally checksum-verified Stripe Terminal 5.8.1 package both report arm64 UUID `6B66F53A-307E-3AD8-AC4E-A2E5AF652AE9` via `dwarfdump --uuid`. The archive contains the Thorbis app and widget dSYMs, but no StripeTerminal dSYM. The [official 5.8.1 release](https://github.com/stripe/stripe-terminal-ios/releases/tag/5.8.1) provides the XCFramework ZIP as its only release asset; the extracted XCFramework contains no dSYM. Stripe's [changelog](https://github.com/stripe/stripe-terminal-ios/blob/master/CHANGELOG.md) states that dSYMs are no longer bundled with the XCFramework.

For future releases, request the authentic 5.8.1 arm64 dSYM for this exact UUID from Stripe through the existing support channel. Verify the returned DWARF file with `dwarfdump --uuid` against the framework in the relevant archive; never substitute another version or an empty/generated placeholder. Include the verified symbol bundle with a future archive before distribution and confirm Xcode's validation result. Preserve each release archive and its app symbols.

Apple's [debugging information guidance](https://developer.apple.com/documentation/xcode/building-your-app-to-include-debugging-information) says to upload symbols with the build for server-symbolicated reports and that Xcode can symbolicate reports locally when the matching dSYM is available on the Mac. This guidance does not establish a supported way to attach a vendor dSYM to an already uploaded build. If Stripe supplies the exact file, local symbolication can be used; independently verify any later App Store Connect upload procedure with Apple before claiming it is supported. Apple's [build metadata guidance](https://developer.apple.com/help/app-store-connect/manage-builds/view-builds-and-metadata/) says App Store Connect downloads are unavailable for submissions from Xcode 14 or later, so downloading symbols from Apple cannot be assumed to recover the missing vendor file.
