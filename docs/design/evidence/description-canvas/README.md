# Description canvas — held prototype

This branch is **not ready for release**. It adds a full-height editing canvas to technician estimate and invoice line editors and estimate-option descriptions, but does not yet satisfy the full requested job, customer, read-only customer-document, or all-description experience.

The current candidate hosts canvases at the new-estimate, estimate-revision and invoice document roots; it checks the current item and original text before applying, and presents long descriptions as two-line previews. Further independent review and UI tests for row replacement and document reload remain release blockers. Finalized and customer-facing documents still need a separate readable drawer. Navigating away from a parent document can still destroy an in-memory canvas draft. The current length limits (200 UTF-16 for estimate lines, 211 Unicode scalars for invoice lines, 500 UTF-16 for options) are server contracts and still prevent genuine long paragraphs from being saved. Do not weaken validation or claim the backend gap is fixed.

Regression evidence: initial baseline `/private/tmp/description-canvas-red2.xcresult` failed because the Show more control was absent. `/private/tmp/description-canvas-discard.xcresult` passed 3 count tests, 9 What's New tests and 3 UI tests on an isolated iPhone 16 simulator: estimate open/edit/discard/reopen/apply, invoice catalog edit/apply, and large-text over-limit retention. A prior run passed the same two ordinary journeys but its largest-text test runner crashed. Screenshots show the normal and largest-text candidate; they do not prove read-only viewing, VoiceOver, RTL, iPad, real server saving or complete long content.

Explicit Cancel on the latest candidate asks before discarding changes; accidental interactive dismissal is disabled when modified. This is not a durable draft or an authorization recovery policy. Code on this branch must not be merged or uploaded until blockers are resolved and independently reviewed.

The current experimental scope guard hides the buffer when actor, workspace, session, authority or inherited editability changes and retires access for the lifetime of that presentation. It does not establish safe recovery across authority changes or survive destruction of the owning document. The estimate edit capability revoke/regrant path was exercised in the preview test described below; other authority changes are not established by that test.

On the held candidate, `/private/tmp/description-canvas-root-final2.log` records the three live-state guards and four simulator journeys passing: revision estimate edit/discard/apply, invoice catalog edit/apply, new estimate edit/apply, and largest-text over-limit retention. `/private/tmp/description-canvas-authority-removal.log` records two additional preview-only simulator journeys passing: revoking and restoring actual session edit authority while unsaved text is open, and removing the actual invoice line while its canvas is open. In each, the canvas hid the buffer, refused Apply, and required explicit discard. These test controls are compiled only in DEBUG and require explicit Paper preview arguments.

These results do not establish durable recovery when the document-owning view is destroyed, or cover customer/finalized document drawers. The server length limits still prevent true multi-paragraph saving; no evidence here establishes real-server persistence. The branch must remain held pending independent review and Release verification.

`/private/tmp/description-canvas-replacement-ui-retry.log` records a passing preview test that reconstructs an estimate draft while its option canvas is open, deliberately reusing the option ID; the canvas locked and required explicit discard. This tests the generation guard through preview reconstruction, not the network reload endpoint. Its first simulator runner exited unexpectedly before the replacement trigger. `/private/tmp/description-canvas-release.log` records a successful Release simulator build of commit 544378e, before the replacement-test fixture was added.
