# Description canvas — held prototype

This branch is **not ready for release**. It adds a full-height editing canvas to technician estimate and invoice line editors and estimate-option descriptions, but does not yet satisfy the full requested job, customer, read-only customer-document, or all-description experience.

Independent review identified release blockers: the drawer is row-owned and needs stable document/row identity and liveness validation before applying; parent disabled state prevents a readable drawer for finalized descriptions; permission loss currently dismisses the canvas and can lose unsaved work; and long descriptions are not yet presented as concise previews with Show more only where useful. The current length limits (200 UTF-16 for estimate lines, 211 Unicode scalars for invoice lines, 500 UTF-16 for options) are server contracts and still prevent genuine long paragraphs from being saved. Do not weaken validation or claim the backend gap is fixed.

Regression evidence: initial baseline `/private/tmp/description-canvas-red2.xcresult` failed because the Show more control was absent. `/private/tmp/description-canvas-discard.xcresult` passed 3 count tests, 9 What's New tests and 3 UI tests on an isolated iPhone 16 simulator: estimate open/edit/discard/reopen/apply, invoice catalog edit/apply, and large-text over-limit retention. A prior run passed the same two ordinary journeys but its largest-text test runner crashed. Screenshots show the normal and largest-text candidate; they do not prove permission changes, row removal/replacement, read-only viewing, VoiceOver, RTL, iPad, real server saving or complete long content.

Explicit Cancel on the latest candidate asks before discarding changes; accidental interactive dismissal is disabled when modified. This is not a durable draft or an authorization recovery policy. Code on this branch must not be merged or uploaded until blockers are resolved and independently reviewed.
