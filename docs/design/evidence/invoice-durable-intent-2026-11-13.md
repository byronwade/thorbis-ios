# Held durable invoice capture intent experiment

This branch is a storage-only prototype, not an editor integration or a releasable recovery feature. The prior in-memory receipt experiment allowed a writer to advance past a capture whose commit result was ambiguous. This experiment registers an exact scoped intent and encrypted payload in a separate SQLite transaction before capture, then keeps the intent in both registered and committed states. All operations using this version of the transaction fence reject an unresolved intent. No intent-clearing or reconciliation API exists; the state intentionally blocks indefinitely.

The `invoice_durable_intent_probe.swift` host run confirms two fence instances block capture, legacy save, begin and recovery while an intent is registered or committed; it also checks the earlier snapshot remains. The `invoice_durable_crash_probe.swift` host run kills separate processes after registration and after committed capture, and verifies another instance cannot advance or recover; two simultaneous processes racing to register admit exactly one. These are macOS host results with synthetic bytes, not iOS file-protection, power-failure, or security evidence. The API was compiled on host using Swift 6 and SQLite. The first test failed because the intent API did not exist before implementation.

Do not integrate: this is not compatible with old binaries or unfenced database writers; it has no authority/session/revision checks, full snapshot proof, observed-commit receipt, authorized reconciliation, owner transfer, disk-full proof, encryption/key management, or database/WAL protection. It stores an additional encrypted payload in the intent. A caller that cannot obtain a registration result cannot resolve it. Existing capture callers do not use the staged API. Crash before commit boundaries and transaction interruption remain to be tested. The host tests do not prove network freshness or financial mutation correctness.
