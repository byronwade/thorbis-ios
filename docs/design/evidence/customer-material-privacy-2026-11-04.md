# Customer estimate material visibility

The server's customer estimate projection folds lines marked `showToCustomer: false` into one Materials line. Customer estimate handoff review, the document book, and legacy read-only estimate paper had rendered raw lines. The existing single-estimate helper also returned raw lines if its hidden-material sum failed. The customer now sees a checked projection or an unavailable-amount message; invoice rendering is unchanged. The signing action compares the same projected base scope while retaining raw amount validation. This is not a new add-on, payment or approval feature.

On unmodified release source, a mounted customer-handoff regression confirmed a private material description appeared (`/tmp/thorbis-material-privacy-red.log`). On frozen commit a39097b, 17 focused amount and customer-review API tests and one mounted hidden-material review → signature/approval test passed (`/tmp/thorbis-material-privacy-green.log`). The focused tests include hidden credits, overflow, wrong currency, matching projected public scope and rejection of the raw private scope. Before/after source fingerprints match (`/tmp/thorbis-material-privacy-green-before.sha` and `-after.sha`).

Independent source review found no additional blocker for the mapped estimate views and signing chain. The mounted test covers the handoff flow only; direct customer book and legacy paper UI, iPad, VoiceOver, device and deployed-server verification were not run. This client projection matches the checked-in server algorithm; it is not proof of hosted server deployment or version. New pre-selection estimate details remain separately held and are not included here.
