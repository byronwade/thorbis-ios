# Startup destination verification

The setting stores a chosen root on this device, scoped to the actor, workspace and API origin. Only currently permitted roots are offered and the saved choice is checked again on launch. Automatic keeps the existing role/layout default. Incoming record, search and schedule requests take priority. Adaptive shells share the last selected root and consume a schedule request once. This does not preserve pushed navigation paths or modal state when the shell changes.

The release-based production source `408c42b` passed seven startup model tests and nine What's New tests on the assigned iPhone simulator (`/tmp/thorbis-startup-xcode.log`); `/tmp/thorbis-startup-before.sha` and `/tmp/thorbis-startup-after.sha` matched. Subsequent reviewed production fix `8c403f9` records a schedule shortcut before adaptive handoff.

The combined DEBUG fixture `154979a` passed seven startup model tests and six mounted UI tests (`/tmp/thorbis-startup-green-xcode.log`); `/tmp/thorbis-startup-green-before.sha` and `/tmp/thorbis-startup-green-after.sha` matched. The mounted tests cover Settings selection, scope-independent launch choice, delayed Automatic Home, internal customer and schedule requests, root continuity between shells, and a simultaneous schedule request and shell switch. The shell switch is forced by a DEBUG fixture on an iPhone simulator; these checks do not establish native iPad behavior, external universal-link delivery, accessibility at large text sizes, or physical-device behavior.

The earlier DEBUG fixture `cb81f52` exposed a stale Customers root on a simultaneous shortcut/shell switch; four cases passed and that case failed (`/tmp/thorbis-startup-fixture2-xcode.log`). Its source was inadvertently changed after all cases reported but before Xcode terminated, so before/after source manifests differ. The failure hierarchy showed Customers on both shells (`/tmp/thorbis-startup-failed-attachments/5CCCB155-84D0-4D9E-811A-4C0D27AC80A2.txt` and `425E7DB4-1095-49B4-AA37-F357888A3980.txt`); exact callback ordering was not instrumented. The later frozen fixture above passed with matching manifests.

Integration `7abf722` is based on release `b48b34d` and has identical production and startup-test files to `8c403f9`; the only intervening changes are build 158/159 release records. Its combined DEBUG fixture adds instrumentation only for the test run, and the exact integrated head has not itself been rerun.

The exact integrated source `a924155` subsequently passed all 16 selected simulator tests: seven startup model and nine What's New checks (`/tmp/thorbis-startup-integration-xcode.log`). The before/after source manifests `/tmp/thorbis-startup-integration-before.sha` and `/tmp/thorbis-startup-integration-after.sha` matched. The mounted UI evidence remains the separate DEBUG fixture described above.

After merge, review identified two further ordering problems: a handled record link could be replaced by the remembered root, and a prior session's global launch latch could prevent the next workspace's preference. Production fix `cda5d18` records the handled target before restoration and scopes handled-navigation state to the session while preserving pending requests. An independent source review found no further confirmed blocker in this narrow change.

The combined DEBUG fixture `9e9ee6d` passed nine startup model and seven mounted UI cases (`/tmp/thorbis-startup-link-fixture-xcode.log`), with matching `/tmp/thorbis-startup-link-fixture-before.sha` and `/tmp/thorbis-startup-link-fixture-after.sha`. These cover a customer request and adaptive switch with a stale remembered Jobs root, plus session-latch and pending-request model checks. The simulated request and forced shell transition do not verify external universal-link delivery, a real account/workspace switch, native iPad behavior, or a physical device. The DEBUG fixture adds test controls and uses equivalent width dispatch; the production fix itself was not run as an exact standalone integration head.

A subsequent review found phone search could overwrite the tablet's remembered place during an adaptive switch. The frozen DEBUG fixture `60be343` reproduced this: its Jobs-root assertion failed while the search query remained visible (`/tmp/thorbis-startup-search-red.log`), with matching before/after source manifests. Production fix `5bf0c07` restores the permitted remembered root before handling a pending search, for either callback order; independent review found no confirmed source blocker.

The combined DEBUG fixture `95e85cd` passed ten startup model and eight mounted UI tests, including the previously failing search transition (`/tmp/thorbis-startup-search-green.log`). `/tmp/thorbis-startup-search-green-before.sha` and `-after.sha` match. The test delivers an internal search request and forces adaptive shells on an iPhone simulator; it does not establish actual Siri delivery, native iPad or physical-device behavior.
