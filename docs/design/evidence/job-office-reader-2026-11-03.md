# Job office instructions reader — held candidate

A technician can read long office instructions without the entire note taking over Overview. Short notes remain fully visible; a long note shows a three-line preview and opens a selectable full-height reader. The reader is read-only: this change does not implement an office-instruction editor or imply that edits can be saved. Existing customer, money, job and activity actions remain available.

Reference: Paper “Thorbis — Schedule Redesign”, Thorbis Mobile, “21 · Job details” (PPL-0), which places the instructions on the job. The shared Thorbis type, colours and native sheet adapt that design. Mobbin examples inspected: [Jira Cloud task description](https://mobbin.com/screens/144e99c7-9f05-4186-9dc1-577435b74f3e) and [Matter summary disclosure](https://mobbin.com/screens/26fb8dde-30ab-4369-b146-5cf351e0e9df). The user requested a full-height reader; those references do not establish a performance improvement.

## Data and offline limits

The job-detail screen's job-record read now performs a fresh live request after a scoped store writes a pending hold. The office note comes only from the store's verified job snapshot, never directly from the generic job cache. The scope includes actor, organization, normalized origin, job, server policy/authority and the current session, authority and API generations. A denial, unfinished request or storage failure fails closed for this note. Shared observable revisions retire snapshots in other mounted views. The general job screen keeps its pre-existing fallback when office verification cannot be established, and a generic notice asks for a connection where appropriate.

Offline note restoration works only for a verified snapshot in the **same session, authority and API generation**. A new app session, authority refresh or API generation requires another successful live job read before this reader can show the note. Legacy unscoped JobDetailCache records do not establish office-note access. This is a material offline limitation compared with the old unscoped note display. Other job consumers and their cache/denial behavior are not covered or fixed here. Persisted grants do not establish instant offline relationship revocation, and signed-device/app-extension behavior is not qualified.

## Storage-failure follow-up (still held)

Independent review found that a successful job read followed by an office-snapshot write failure could leave the entire job blank. The injected DEBUG regression reproduced that failure in `/private/tmp/thorbis-job-office-completion-red.log`. A second review found that a failed pre-commit store read needed to be distinguished from an old attempt. The follow-up retains the general job when safe while keeping the office note hidden; a storage-read failure triggers a new fresh general job read rather than publishing an unverified earlier response.

On frozen source, 19 store/release-note tests and seven UI cases passed, including both injected storage failures, both denial/offline cases, short/long notes and largest text (`/private/tmp/thorbis-job-office-storage-final.log`, `/private/tmp/thorbis-owner-ui-derived/Logs/Test/Test-Thorbis-2026.11.03_12-29-11--0500.xcresult`). Hashes matched `/private/tmp/thorbis-job-office-storage-final-manifest.txt`. This does not remove the material same-session-only offline limitation described above. Do not release this candidate until cold-offline behavior is resolved and independently verified.
