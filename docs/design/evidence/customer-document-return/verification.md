# Customer estimate return to job documents

Customer mode now offers a route from an individual estimate back to the same job document book, including after a successful approval; the separate owner-authenticated hand-back remains available. Returning first invalidates the current estimate read and marks retained rows stale, then launches a tenant/job/capability-guarded refresh without blocking navigation. A confirmed matching approval response may update an existing linked record but is still stale until refreshed; a public approval with no returned aggregate never invents a status. Stale status is explicitly labeled as needing refresh. No combined approval or bill-once billing is claimed.

On the candidate source, `/private/tmp/customer-return-final8-tests.log` and `.xcresult` record 25 job-document unit tests, 9 release-note tests and 7 customer document-book UI tests, all passing on the iPhone SE (iOS 18.2). The focused UI tests cover signed approval and returning to another estimate, failed membership refresh, public option approval with no returned aggregate, hand-back, and existing document paging. The local-only transport uses isolated preview signature uploads; no real financial action was made. `/private/tmp/customer-return-handback-retest.log` records the specific hand-back regression's passing retest.

The first signing run failed because the preview used a nonresolving sample storage host; the DEBUG-only transport was corrected. A subsequent hand-back test exposed nested navigation staying on the estimate; clearing both nested destination bindings before hand-back fixed the focused test and the seven-test suite. The pre-fix UI red test for the new return action never executed because the simulator service failed; no red/green claim is made.

The separate invoice hand-back probe is in progress and is not part of this change. VoiceOver, iPad, real workspace signing, hanging-network UI behavior, and the independent multi-estimate handoff are not newly tested here. Add-on quoting and bill-once backend support remain separate unfinished work.

## Invoice hand-back follow-up

A focused probe of invoice presentation reproduced the same nested-navigation problem: after entering invoice signing, returning to the invoice and tapping Done, the technician unlock screen did not appear (`/private/tmp/customer-invoice-handback-probe.log`). The first probe failed earlier due to a test selector matching both Back buttons; its corrected selector reached the actual failure. Invoice completion now uses the same destination reset as estimate completion, without changing invoice signing, payment or money logic. On the follow-up source, `/private/tmp/customer-invoice-final-tests.log` and `.xcresult` record 25 job-document and 9 release-note unit tests and 8 customer document-book UI tests, all passing on the iPhone SE (iOS 18.2), including both estimate and invoice hand-back. Read-only paper hand-back has not been reproduced or changed.
