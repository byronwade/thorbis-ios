# Job-photo thumbnail investigation — 2026-10-30

Scope: read-only inspection of `/private/tmp/thorbis-job-cart-backend` (origin `Thorbis-TanStack`) and `/private/tmp/thorbis-ios-visual-main`. The backend checkout has unrelated pre-existing changes. No backend files, production data, or deployment were changed. Findings describe the checked-out source, not deployed capability.

## Current contracts

- `/private/tmp/thorbis-job-cart-backend/domains/media/src/queries.ts:61`: `downloadUrl` resolves an asset inside the session organization, authorizes `job.view` against its owning job, requires `uploadState == stored`, then asks the storage port for a signed URL to that asset's object. The comment says thumbnails/derivatives inherit the same authorization; it does not implement or generate a thumbnail.
- `/private/tmp/thorbis-job-cart-backend/services/api/src/app.ts:5078` and `services/api/src/routes/manifest.ts:4777`: `GET /v1/media/:id/download` exposes that signed-original capability. `/private/tmp/thorbis-job-cart-backend/domains/media/src/ports.ts:69` and `services/api/src/composition/r2-media-storage.ts:125` define and implement `createDownloadUrl` for an existing object key, without a size/resize variant.
- `/private/tmp/thorbis-job-cart-backend/domains/media/src/schemas.ts:62` has optional `sourceAssetId` for immutable derived assets. `/private/tmp/thorbis-job-cart-backend/domains/media/src/derived-asset.ts:1` enforces the derived asset belongs to the same tenant and job as its source at insertion. There is no explicit thumbnail type, bounded thumbnail generation, or query for a thumbnail discovered in the checked-out code. This foundation does not by itself establish a thumbnail lifecycle.
- `/private/tmp/thorbis-job-cart-backend/domains/jobs/src/queries.ts:160` legacy `getJobPhotoContent` checks the owning job and tenant-bound key, then returns the full stored image. `/private/tmp/thorbis-job-cart-backend/domains/jobs/src/schemas.ts:748` caps legacy upload size at 15 MiB; this is not a thumbnail response.
- `/private/tmp/thorbis-ios-visual-main/Thorbis/Sources/MediaTransfer.swift:127` obtains the modern signed URL and uses `URLSession.download(for:)` for the full original. Its 50 MiB `maxPreviewBytes` check happens after the download. Metadata filtering on the original size cannot guarantee an on-wire transfer limit.
- `/private/tmp/thorbis-ios-visual-main/Thorbis/Sources/MediaThumbnail.swift:8` scopes the memory cache by actor, organization, session generation, authority revision, policy version, job, and a per-view authorization epoch. It down-samples only after downloading and removes the temporary original. This is not a persistent offline thumbnail cache; new presentations may fetch again.

## Proposed next slice and qualification

1. Add a media-owned thumbnail derivative lifecycle and job-authorized read contract, with tenant-derived object keys and original/derivative provenance. Use a deterministic bounded output (encoded bytes, dimensions, and allowed image formats) and enforce limits during processing and delivery; don't rely on caller-supplied size metadata. Retain originals and fail closed for foreign/missing/archived/out-of-scope media according to the existing policy.
2. Design generation/backfill, retries, idempotency, resource and decompression-bomb limits, orientation, cancellation, stale derivatives, retention, and failure/partial states. Document tenant placement and feature exposure before adding storage/worker paths. Verify whether existing signing/expiry and immutable cache policies meet revocation requirements; a minted signed URL remains usable until expiry.
3. On iOS, request only a bounded visible set, preserve direct Photos navigation and truthful counts, honor session generation/authority/policy changes, and avoid customer-wide fan-out. A scoped cache needs an explicit invalidation and offline policy rather than silently reusing bytes across actors or workspaces.
4. Test tenant and job isolation, denied/revoked access and concurrent session changes; original-to-derivative integrity, malformed/oversized inputs and hard byte limits; failure/retry, partial and offline states; actual decoded pixels, small/large text, VoiceOver and iPad; plus bandwidth and repeated-navigation measurements. Test actual deployed/exposed behavior before claiming availability.

The earlier opt-in preview experiment in `/private/tmp/thorbis-ios-job-photo-strip` is held: it duplicated the existing Photos navigation, its fixture did not establish real downloaded pixels, and metadata size was not a hard transfer cap.
