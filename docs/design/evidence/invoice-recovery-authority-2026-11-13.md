# Invoice draft reconciliation authority: inspected primitives

This document maps existing mechanisms; it does not certify a recovery flow or confer authorization.

`SessionController` publishes an authenticated `user`, `activeOrganization`, `generation`, `authorityRevision`, `policyVersion`, `authorityGeneration` and `isOffline`. `can("invoice.edit", feature: "invoicing")` requires ready phase, unexpired session and authority, capability, and enabled/released/entitled feature. Server catalog loading checks actor and organization binding before publishing capabilities; offline state may still use cached authority. `APIClient.normalizedOrigin` identifies the selected origin. `liveFieldInvoice(id)` refuses saved-copy results but, on this base, is not wrapped in the task-local URL cache bypass; the separate financial-live-read branch corrects that and still awaits integrated iOS tests. The GET result supplies invoice, organization, customer, job, draft status and `linesRevision`. The server's line replacement receives `expectedLinesRevision`; this is a concurrency condition on a later mutation, not authorization to disclose a local draft.

The held `InvoiceDraftRecoveryScope.matches` compares invoice, organization, customer and job. Its full `InvoiceDraftRecovery` contains an entire baseline invoice and restores only when the current server record equals that baseline, state is idle, and caller-supplied `fresh`, `canEdit` and `noUnresolvedAttempts` flags are true. Those flags are ordinary booleans, not an attestation. `InvoiceLineEditorView.reloadLatest` fetches a live invoice but by itself does not bind an asynchronous response to session generation, authority revision, active origin, or pending marker before replacing editor state.

A conservative future coordinator can use existing primitives as follows, but is NOT implemented: on the main actor require ready online session, capture actor/org/origin/generation/authorityRevision, check invoice view and edit capability; perform the corrected no-cache `liveFieldInvoice` GET; after the await recheck the entire captured context, capabilities and offline state, exact scope and draft status; inspect encrypted unresolved intent only, decrypt with the scoped key, then verify a valid full snapshot and exact stored baseline equality. If a previous snapshot and an uncertain candidate both exist, present both as unsent local versions and require an explicit user's selection; a known or unknown server submission marker must independently block mutation. On selection, a storage transaction must compare exact intent token/phase/owner/sequence/ciphertext and head version observed, retain every snapshot including rejected/ambiguous ones, reject competing writers, and only then transition the selected full snapshot to an independently durable state. Recheck session authority immediately before exposing or applying selection, and use the server's `expectedLinesRevision` on eventual save. If the server record or scope changed, access was revoked, the payload cannot decrypt, a write may be pending, or the two local candidates cannot be verified as complete snapshots, leave the intent fenced and show a truthful recovery/review state. A separately designed idempotent local transition is needed so death or a thrown response after reconciliation cannot silently discard a choice.

Gaps: no session-issued capability object for this coordinator, no atomic coupling between main-actor authority and background SQLite transaction, no implemented explicit selection screen or authorized resolution, no verified conditional/idempotent outcome for already-sent direct requests, no iOS Keychain/SQLite WAL and data-protection tests, and no inter-version guarantee preventing older code from bypassing the fence. A cached capability or a caller-created Boolean is insufficient. None of the held host tests prove this future flow.
