# Draft recovery verification, 2026-11-02

The first Xcode run compiled the application and test bundles on iOS Simulator and passed 19 selected draft-store, estimate-recovery, estimate-editor and invoice-editor unit tests. Existing unrelated test targets emitted actor-isolation and deprecation warnings. The UI run did not complete: its first interrupted-create test hung after Save. A live process sample identified a deadlock in the debug-only `EstimateRecoveryPreview`: a mock response held its counter lock while a `UserDefaults` notification waited on SwiftUI, while the main thread tried to read the counters under the same lock. This was introduced by the relaunch test fixture, not established as a production screen failure.

The UserDefaults write was moved outside that lock. A subsequent exact-source Xcode run on a dedicated iOS 26.3 simulator compiled successfully and passed 20 selected unit tests and three UI tests. The UI tests terminated and relaunched during estimate creation and job linking, verified that relaunch sent no automatic writes, retried the known link after fresh checks without another create, and injected a failed local-draft removal after a successful link. The rerun log is `/tmp/thorbis-draft-recovery-rerun.log`. The original interrupted run's log is `/tmp/thorbis-draft-recovery-test.log`; its sampled stack is `/tmp/draft-held-app.sample`.

Production job-link retry relies on the verified deployed same-job idempotency contract: Vercel alias `app.thorbis.com` pointed to production deployment `dpl_2esnPC1XeXSkLxTYyvNZXA1kUmz9`, which GitHub records at `001c3ab`; that revision returns the existing link for the same job and estimate. No production mutations were used to verify this.

An optimized standalone Mac-host benchmark of the actual protected store wrote a synthetic 500-line draft 100 times. Its JSON was 208,528 bytes; write median was 2.20 ms, p95 2.47 ms and maximum 2.77 ms. A one-line draft had a 0.37 ms median. An iOS simulator unit test then wrote an actual 500-line editor snapshot 50 times: 213,612 encoded bytes, 3.60 ms median, 4.43 ms p95 and 7.52 ms maximum. These figures do not measure SwiftUI rendering, an iPhone, or worst-case unsupported input. The current synchronous writes preserve a completed write before the caller proceeds but can stall typing; blindly moving them to a background queue would allow immediate termination before the last queued edit reaches disk. Physical-device profiling remains necessary; an asynchronous redesign needs a durable journal or a clearly stated loss window.
