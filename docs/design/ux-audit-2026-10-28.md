and make huge UX improvements everywhere ... including the side bar and sidebar animations, using
design.thorbis.com."

## Batch 1 (this branch)

tokens, `inkCommit()`, `PressStyle`, `RowPressStyle`, `SkeletonRows`), `App.swift` (`ErrorBanner`),
`PaperComponents.swift`, `PaperWorkViews.swift`, `PaperJobDetailView.swift`, `PaperCustomerViews.swift`,
`Screens.swift`, `LoginView.swift`, `ServiceLocationSheet.swift`, `MediaView.swift`, `ScheduleMapView.swift`,
`InvoicePaymentCollection.swift`, `WorkspaceViews.swift`. Tests: `AppearanceTests` covers ink contrast
(7:1 in every appearance) and the two-weight/12pt floor.

`PaperHeader` is untouched in batch 1 so it does not collide with the side menu PR; batch 2 takes it.

## Batch 2

Items 13–17: side menu motion, modality, anatomy and header grammar, on top of #15 and #17.

## Batch 3

Items 18–20 and 22: two-line job rows with customer, time and number; row press fill; long-press menus
on job and customer rows; Schedule header without the chip band; share text in words.

## Batch 4

Item 23 and the remaining sheet radii. New customer, contact and service location sheets: Return moves to
the next field and the last field saves; the keyboard type and autofill hints match each field; Cancel is a

zooms; fields use the control radius with a foreground focus ring. A swipe can no longer throw away typed
work in New job, New customer or the pause sheet. Sheets use the 14 card radius.

screens: cards 14, controls and notice wells 12, status badges capsules (MA-10). The job note send circle is ink
(MA-08). Pushed-screen titles are 24/500 on the type ramp (MA-09).

## Batch 13: new job finishes at the thumb, customers are searchable

- **Create sits at the bottom:** the small arrow in the top corner is gone. A full-width ink "Create job" button rides above the keyboard (MA-08, MA-12). After a partial save it reads "Try again" and the error message says so.

## Batch 14: Unscheduled shows how long each job has waited

## Batch 15: tabs stay pinned on the job and customer pages

- **Pinned tabs:** on a job (Overview, Estimates, Invoice, Activity, Photos) and on a customer (Overview, Jobs, Activity), the tab strip pins under the navigation bar once the header scrolls away. ## Batch 46: every load error offers Try again

- **Finding:** when Estimates, Invoices, an estimate or an invoice failed to load, the screen showed the error banner with no way forward except pull-to-refresh, which nobody finds on a blank detail screen. MA rule: an error is body words, a tinted mark and one Try again.
- **Fix:** the two list screens pass `load()` to `ErrorBanner`, so the banner shows Try again. The two detail screens offer Try again only while the record has not loaded. When the record is on screen and an action fails (send, approve, decline, void), the banner explains without offering a reload, because reloading would not retry the action.
- **Checked, not changed:**
  - Icon-only buttons in the owned files all carry an accessibility label or a text label. The five flagged by the sweep wrap `PaperMenuRow`, `commercialAction` or text rows.
  - The busy spinner inside the payment-method row is an in-place busy mark, not a page load, so it stays.

## Batch 47: closeout and follow-ups load retries

- **Finding:** the Wrap up (closeout) and Follow-ups screens showed a load failure with no Try again. These are the same gap batch 46 closed on estimates and invoices.
- **Fix:** Wrap up offers Try again while the checklist has not loaded. Follow-ups offers it while the list is empty. When the content is on screen, an action failure (acknowledge, complete, request, resolve) explains itself without a reload button.
- **Checked, not changed:** the payment-collection error banners (payment, refund, receipt) report action failures. The action's own button is the retry, so a second Try again would be ambiguous.

## Batch 48: success haptics on every commit

- **Finding:** only two commits gave a success haptic: creating a job and moving a job's status. Completing a job, sending or approving an estimate and issuing an invoice finished silently, so the tech had to look at the screen to know whether the server took it. These are often done one-handed in the field.
- **Fix:** `.sensoryFeedback(.success, …)` fires on a counter that bumps only after the server confirms the action. It covers Wrap up (complete job), estimate Send and Approve, and invoice Issue. Decline gets no success haptic, because it is not a win.
- **Checked, not changed:** destructive confirmation dialogs already lead with the verb and name the object ("Cancel job", "Remove {contact}", "Refund {amount}", "Discard changes"), so nothing needed to change.

## Batch 49: payment success haptic and keyboard exits

- **Finding:** recording a payment, the most important commit in the app, closed the sheet with no haptic. The sheet dismisses on success, so a view-bound `sensoryFeedback` would never play.
- **Fix:** a `UINotificationFeedbackGenerator` success fires right before the sheet dismisses.
- **Finding:** the new-estimate price field uses a decimal pad, which has no return key, so the keyboard could only be dismissed by scrolling. Wrap up (the unpaid-reason fields) and Follow-ups (the request form) had no way to drop the keyboard at all. MA-16 says a number pad gets one Done above it, and forms dismiss the keyboard on scroll.
- **Fix:** new estimate gets the shared `keyboardDoneButton()`. Wrap up and Follow-ups get `.scrollDismissesKeyboard(.interactively)`, which matches New job, the contact sheet and the payment sheet.

## Batch 50: rows that grow with Dynamic Type

- **Finding:** at accessibility text sizes, the job rows already wrap their title to three lines, but the estimate and invoice rows (`PaperDocumentRow`), customer rows, a customer's job rows and location rows stayed at one line. At AX sizes that line holds two or three words before "…", so a customer named "Henderson Plumbing & Heating" read as "Henders…". Two fixed heights also clipped grown text: the contact sheet's text fields (48) and the schedule sheet header (44).
- **Fix:** those rows follow the job-row pattern. Titles allow 3 lines and subtitles 2 at accessibility sizes, and they stay on one line at standard sizes, so the standard layout is unchanged. The two fixed heights become `minHeight`.
- **Checked, not changed:** `PaperDocumentRow` already combines its children into one VoiceOver element, and job rows read as one element through their NavigationLink.

## Batch 51: Reduce Motion on every owned animation

- **Finding:** only the side menu honoured Reduce Motion (MA-03: a 150ms fade instead of the spring). The search reveal on Jobs, Schedule and Customers, the tab strip's auto-scroll, and the job page's jump to the Invoice tab all ran their full spring or default animation whatever the setting.
- **Fix:** a shared `withMotion(_:_:)` in Theme swaps in a 150ms ease-out when Reduce Motion is on and otherwise runs the animation as written. All five owned `withAnimation` calls now go through it, so the whole app follows one motion rule.

## Batch 52: find an invoice by customer or number

- **Finding:** Invoices had no search, so when a customer called about a bill the tech had to scroll the whole list. Estimates had search, but only on the title. A customer's name or the EST number on the PDF the customer was reading found nothing, and an empty search showed a blank screen.
- **Fix:** Invoices gets `.searchable`, matching the customer name or INV number. Estimates now matches title, customer or EST number. The prompts say what can be typed, and both lists show the shared `PaperEmptyState.search` when nothing matches.
- **Checked, not changed:**
  - `PressStyle` already drops its scale under Reduce Motion. `RowPressStyle` only changes fill, which is fine.
