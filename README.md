# Thorbis for iOS

Native Swift field app for Thorbis. A technician signs in, sees today's route, moves a job from
driving to done, adds notes and photos, looks up customers, sends estimates and issues invoices.
It is a thin client of the Thorbis API (`https://app.thorbis.com`); business rules stay on the server.

- **Swift 6, SwiftUI, iOS 18**, iPhone and iPad.
- **`Core/`** is the `ThorbisCore` Swift package: models, the `ThorbisAPI` client, the job
  workflow, agenda grouping and formatting. It has no UIKit/SwiftUI and its tests run on macOS and Linux.
- **`Thorbis/`** is the SwiftUI app. Design follows [design.thorbis.com](https://design.thorbis.com)
  (Native contract HIG-001–022): system text styles, native controls, ink commit buttons, the electric
  blue accent only for focus and selection, status as a word before a colour.
- The project is generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen) from `project.yml`;
  the `.xcodeproj` is not committed.

## Build and run

```sh
brew install xcodegen
xcodegen generate
open Thorbis.xcodeproj           # pick an iPhone simulator, Run
swift test --package-path Core   # core tests (also run on Linux in CI)
```

Command line simulator build and tests:

```sh
xcodebuild -project Thorbis.xcodeproj -scheme Thorbis \
  -destination 'platform=iOS Simulator,name=iPhone 16 Pro' CODE_SIGN_IDENTITY=- test
```

### Launch arguments (Debug builds only)

| Argument | Effect |
| --- | --- |
| `--ui-fixture` / `--preview` | Signs in to an in-memory demo workspace (Reyes Plumbing). No network. |
| `--reset` | Clears the saved server and session before launch. |

Release builds compile the fixture out; `scripts/testflight.sh` refuses to upload a binary that contains it.

### Servers

Production is the default. **Account → Server** (or the server link on sign-in) switches to a local
API at `http://127.0.0.1:8788` or a custom HTTPS URL. Against a loopback API the sign-in screen offers
**Local dev identity**, which sends the dev headers only the local API accepts.

## TestFlight

On a Mac signed in to the Apple Developer team that owns `com.thorbis.field`:

```sh
APPLE_TEAM_ID=XXXXXXXXXX BUILD_NUMBER=<next build> scripts/testflight.sh
```

It regenerates the project, runs the core tests, archives a Release build with a timestamp build
number, checks the binary for fixture data, and uploads it to App Store Connect. The build appears in
TestFlight after processing. The App Store Connect app record must exist first (see
[Release/Checklist.md](Release/Checklist.md)).
